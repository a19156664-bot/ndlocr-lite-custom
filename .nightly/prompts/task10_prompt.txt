2. ROOT CAUSE - ALREADY DIAGNOSED. DO NOT RE-INVESTIGATE.
--------------------------------------------------------------------------------
The commander captured the real traceback by running the app headlessly:

    File ".../flet/core/control.py", line 561, in _build_command
        self.before_update()
    File ".../flet/core/container.py", line 234, in before_update
        self._set_attr_json("image", self.__image)
    File ".../flet/core/control.py", line 202, in _convert_attr_json
        json.dumps(value, cls=EmbedJsonEncoder, separators=(",", ":"))
    ValueError: Circular reference detected

Explanation:

  - `custom_gui/viewer.py` defines `class ImageViewer(ft.Container)`.
  - `ft.Container` ALREADY defines a property named `image`. It is a decoration
    property and expects a `DecorationImage`, not a Control. Verified:
        isinstance(getattr(ft.Container, 'image', None), property)  -> True
        ft.Container().image                                        -> None
  - `ImageViewer.__init__` does `self.image = ft.Image(...)`, which overwrites
    that reserved property with a Control.
  - When flet updates the Container it calls `before_update()`, which serialises
    the `image` property to JSON. A Control holds references back to its parents,
    so json.dumps hits an infinite loop and raises
    "ValueError: Circular reference detected".

Why it appeared only now: previously the code only called `self.image.update()`
(updating the child), so the Container itself was never serialised. The most
recent change added `self.update()` in the zoom handlers and `page.update()` in
main(), which finally triggers `Container.before_update()` and exposes the bug.
