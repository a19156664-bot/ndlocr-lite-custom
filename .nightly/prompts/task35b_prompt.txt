================================================================================
1. PROBLEM ONE - tests/test_save_direct.py::test_d_overwrite_dialog
================================================================================
It fails on every run:

    with open(csv_path, "r") as f:
        assert f.read() != "SENTINEL"
    UnicodeDecodeError: 'cp932' codec can't decode byte 0xef in position 0

The commander runs on Japanese Windows, where the default text encoding is
cp932. The exported CSV is written as utf-8-sig, so its first byte is the BOM
(0xEF), which cp932 cannot decode.

This is worse than a red test. The commander injected a deliberate defect
(making `_start_export` skip the overwrite check and write immediately) and
the test failed in exactly the same way it fails against CORRECT code. It
cannot tell the two apart, so it proves nothing. This project has now shipped
SEVEN tests that could not detect the bug they were written for.

WHAT TO DO

    Every `open()` in tests/test_save_direct.py must name its encoding
    explicitly. There is no correct default here.

        a CSV written by the app  -> encoding="utf-8-sig"
        a TXT written by the app  -> encoding="utf-8"
        a file the TEST writes as a sentinel -> encoding="utf-8", and read it
            back with the same encoding

    Do not "fix" this by catching the exception, by reading bytes and calling
    .decode(errors="ignore"), by comparing os.path.getmtime, or by asserting
    the file merely changed size. The test must read the text and compare it.

    While you are in the file, check EVERY other open() for the same bug, not
    only the one that happens to fail today. test_b and test_e also read the
    exported files.
