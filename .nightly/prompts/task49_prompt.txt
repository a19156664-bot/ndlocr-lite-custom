## 1. What is wrong, measured

### 1-1. The status bar never refreshes

`_on_marks_to_rects_click` sets `self.latest_region_info` and then calls
`self._update_selections_ui()` and `self._persist_work_state()`.
**Neither of those calls `self._update_status()`**, and `_update_status` is the
only thing that pushes `_get_status_message()` into `self.status_text`.

The commander measured this on 2026-08-28 with a real `ft.Text` status bar:

    before the press : ... | Mode: SELECT | OCR not started | Last: None
    internal value   : マークから 0 個の矩形を作りました（囲み 0・傍線 0）
    after the press  : ... | Mode: SELECT | OCR not started | Last: None

The rectangles are created correctly. **The user is simply never told.**
Every other button in this file calls `_update_status()`; this one does not.

### 1-2. The tests cannot see it, because they replaced it

`tests/test_marks_to_rects.py` has a helper `get_app()` that does this:

    def mock_update_status():
        pass
    app._update_status = mock_update_status

    def mock_update_selections_ui():
        pass
    app._update_selections_ui = mock_update_selections_ui

    def mock_persist_work_state():
        pass
    app._persist_work_state = mock_persist_work_state

**Three of the four things the handler does are replaced by empty functions.**
So no test in this file can detect a defect in the status bar, in the selections
UI, or in persistence. This is the failure mode this project has rejected twelve
times: the test mocks out the thing under test.

**The mocks are not necessary.** The commander ran the handler on 2026-08-28
with all three methods REAL, against a real page, using only
`unittest.mock.MagicMock()` as `app.page` and a real `ft.Text` as
`app.status_text`. Everything ran, and `_update_status()` produced the full
status line. The comment "Mock update status to prevent UI exception" describes
a problem that does not exist under that setup.
