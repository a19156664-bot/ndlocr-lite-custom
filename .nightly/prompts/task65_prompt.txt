================================================================================
Task 65: Grips on the selected frame of the confirmation viewer -- drag a
         grip to resize the frame, drag the middle grip to move it
         (ids, labels, list order and corrected texts never change)
================================================================================

This order is Task 65 of the commander's local ROADMAP (not on GitHub; you
do not need it: everything is in this order).

## 1. Purpose and background

In the confirmation viewer a frame (SelectionRect) can be drawn, selected
and deleted, but once drawn it cannot be moved or resized: today the
only way is to delete it and draw it again. The approver asked (2026-10-09) to
move / resize frames with the mouse, and chose this design ("案甲"):

  - Only the SELECTED frame (self.active_region_id) shows grips: 8 small
    squares (corners and edge middles, 10 px) to resize, and 1 circle in the
    middle (14 px) to move. Hovering a grip shows a resize / move mouse cursor
    (a static property of each grip, so no server round trip on hover).
  - While a grip is dragged only an orange preview frame moves. The frame
    itself changes once, on release, and is saved then.
  - Dragging anywhere else keeps today's behaviour (draw a new frame).
    This matters: on 70 of 241 saved pages a frame is drawn INSIDE another
    frame, so "drag inside a frame = move" would break the approver's work.

Rules that must keep working:
  - rect_id, label, list order and self.edits NEVER change when a frame is
    moved or resized. Only bbox changes (original image pixels).
  - The frame stays inside the image and never gets smaller than 4 px.
  - No change while a card is being edited (self.editing_region_id is set):
    a message in self.latest_region_info instead.
  - Grips only in Select mode, never on a hidden frame.
  - The grips layer is the LAST control of self.stack (above the gesture
    detector AND above the inline editor, which opens right under a frame
    and would otherwise cover the bottom grips).
    tests/test_inline_edit.py test_f only requires inline_editor_layer after
    gesture_detector; that stays true.

+def adjust_bbox(
+    bbox: Tuple[float, float, float, float],
+    grip: str,
+    dx: float, dy: float,
+    img_w: float, img_h: float,
+    min_size: float = 4.0
+) -> Tuple[float, float, float, float]:
+    """Move ("move") or resize (a grip made of n / s / e / w) a frame by dx, dy
+    original pixels. The frame stays inside the image and never gets smaller than min_size."""
+    x1, y1, x2, y2 = bbox
+    if grip == "move":
+        dx = max(-x1, min(dx, img_w - x2))
+        dy = max(-y1, min(dy, img_h - y2))
+        return (x1 + dx, y1 + dy, x2 + dx, y2 + dy)
+    if "w" in grip:
+        x1 = min(max(0.0, x1 + dx), x2 - min_size)
+    if "e" in grip:
+        x2 = max(min(img_w, x2 + dx), x1 + min_size)
+    if "n" in grip:
+        y1 = min(max(0.0, y1 + dy), y2 - min_size)
+    if "s" in grip:
+        y2 = max(min(img_h, y2 + dy), y1 + min_size)
+    return (x1, y1, x2, y2)
