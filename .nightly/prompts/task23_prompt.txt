1. PURPOSE
--------------------------------------------------------------------------------

                                   img_w=2048, img_h=1446, ...)

The user scans historical documents. A scanned volume is one FOLDER of page
images. The human owner has decided the entry point:

     Move through them with a Next button and Ctrl+N."

4. DEFINITION OF DONE
--------------------------------------------------------------------------------
[A] New PURE module `custom_gui/image_sequence.py`. It must NOT import flet.

        SUPPORTED_EXTENSIONS = (".jpg", ".jpeg", ".png", ".tif", ".tiff")

        def list_images_in_folder(folder) -> List[str]
            # Full paths of supported images DIRECTLY inside `folder`
            # (do not recurse into sub-folders).
            # Extension matching is CASE-INSENSITIVE: "0002.JPG" counts.
            # Sorted by file name, ascending, so 0001 comes before 0002.
            # A folder with no images returns [] - not an error.

        class ImageSequence:
            def __init__(self, paths: List[str])
            current() -> Optional[str]      # None when the list is empty
            index    -> int                 # 0-based; -1 or 0 when empty, your
                                            # choice, but document it
            count    -> int
            has_next() -> bool
            has_prev() -> bool
            next() -> Optional[str]         # advances and returns the new current
            prev() -> Optional[str]
            goto(i) -> Optional[str]

        Navigation must CLAMP at the ends. It must NOT wrap around: calling
        next() on the last image leaves you on the last image. Document this.

[B] "Open Folder" button.
    - Add it to `self.controls_row` with ft.Icons.FOLDER_OPEN.
    - It calls `self.file_picker.get_directory_path(...)`.
    - Reuse the EXISTING `self.file_picker`; do not create a second one. Its
      `on_result` handler currently assumes a save-file result, so you must make
      that handler distinguish between "the user was saving a file" and "the user
      was choosing a folder". State clearly in your report how you did this.
    - A folder containing no supported images must show a clear status bar
      message such as "No images found in <folder>" and must NOT change the
      currently displayed image.

[C] Navigation controls.
    - "Prev" and "Next" buttons in the toolbar (ft.Icons.NAVIGATE_BEFORE /
      NAVIGATE_NEXT).
    - Ctrl+N moves to the next image, via `page.on_keyboard_event` checking
      `e.key` and `e.ctrl`.
    - Buttons must be DISABLED (not merely inert) when there is nowhere to go:
      Prev on the first image, Next on the last, and both when no folder is open.
    - The status bar must show the position, e.g. `2 / 12`, alongside the
      existing fields.

[D] Switching image actually switches everything.
    When the current image changes:
      - `self.image_src` and `self.image_control.src` point at the new file.
      - `self.img_w` / `self.img_h` are the NEW image's real dimensions, read
        with Pillow. Do not assume 2048x1446.
      - The zoom resets to fit the new image (`calculate_fit_scale`) and
        `offset_x` / `offset_y` reset to 0.0.
      - The Selections panel, rectangles and highlights show the NEW image's
        data, not the previous image's.

[E] Per-image state is REMEMBERED. This is the core requirement.
    - Each image keeps its OWN rectangles and its OWN OCR results.
    - Going to image 2, drawing a rectangle, going back to image 1 and returning
      to image 2 must show that rectangle again.
    - OCR results are CACHED per image: returning to an image that has already
      been OCR'd must NOT re-run OCR. It takes about 50 seconds.
    - Keep this state in a small, GUI-free structure so it is testable, for
      example a dict keyed by image path holding a SelectionContainer, the OCR
      line list and the OcrState.

[F] OCR stays asynchronous and lazy.
    - OCR runs only for the image being displayed, and only if it has not been
      run for that image yet.
    - It must keep using `page.run_thread` and must NOT block the UI. The whole
      point of Task 12 was that the window stays usable; do not regress it.
    - If the user moves to another image while OCR is still running, the app must
      not crash and must not write the finished results onto the WRONG image.
      State in your report how you prevented that.
    - The progress indicator and status text keep working per image.

[G] Backwards compatibility on startup.
    With no folder chosen, the application must still start on the bundled image
    `resource/digidepo_2531162_0024.jpg` exactly as it does today, reading its
    size with Pillow rather than the hardcoded 2048x1446.

[H] Tests - `tests/test_image_sequence.py`, no GUI, no real OCR.
    Concrete assertions, not properties. Use pytest's `tmp_path` to build a fake
    folder. At minimum:
      (a) A folder containing 0002.jpg, 0001.png, 0003.JPG, notes.txt and a
          sub-folder returns EXACTLY 3 paths, whose basenames are
          ["0001.png", "0002.jpg", "0003.JPG"] in that order. This covers
          sorting, case-insensitive extensions, non-image rejection and
          no-recursion in one assertion.
      (b) An empty folder returns [].
      (c) ImageSequence over 3 paths: index starts at 0; next() twice reaches
          index 2; a THIRD next() leaves index at 2 and has_next() is False.
      (d) prev() from index 0 leaves index at 0 and has_prev() is False.
      (e) goto(1) then current() returns the second path; goto(99) does not
          raise and does not move past the end - assert the exact resulting
          index.
      (f) ImageSequence([]) - current() is None, count is 0, has_next() and
          has_prev() are both False, and next() does not raise.
    Add a test for the per-image state store from [E] asserting that rectangles
    added while on image A are still there after switching to B and back to A,
    and that the OCR cache for A is not cleared by visiting B.

[I] Regression safety.
    - `python -m pytest tests/ -v` must pass completely (57+ tests).
    - Do NOT modify custom_gui/ocr_bridge.py, custom_gui/region_filter.py,
      custom_gui/selection.py, custom_gui/text_assembler.py,
      custom_gui/exporter.py.
    - Do not modify the pure functions in custom_gui/viewer.py.
