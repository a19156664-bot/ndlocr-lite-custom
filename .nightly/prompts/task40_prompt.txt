THE USER'S DIAGNOSIS IS THE PRIMARY ONE. When the page has no rectangles and
no mark, `_start_export("current")` returns at line ~852 after writing

    if not rects and not self.mark:

The real defect is that a refusal is invisible. Sections 2 and 3 below cover

This is NOT a mystery to investigate - every cause is printed below.
Implement the fix.

================================================================================
2. SECOND PATH - the overwrite confirmation dead-ends the keyboard
================================================================================
`_start_export` (custom_gui/app.py line ~877) branches on whether the output
file already exists:

    if os.path.exists(csv_path) or os.path.exists(txt_path):
        self._show_overwrite_dialog(scope, csv_path, txt_path)
    else:
        self._do_write_and_show_done(scope, csv_path, txt_path)

The per-page output is `<image stem>.csv` / `.txt`, so the SECOND time a page
is saved the file exists and the flow stops at the 上書き確認 dialog. Task 38
deliberately gave that dialog NO autofocus, so Enter does nothing there -
which means `Ctrl+S` followed by `Enter` dead-ends from the second save
onward. The 広告 / 表紙 buttons also create `<stem>.txt` the moment they are
pressed, so almost every page the user has touched hits this.

The all-pages output is `<folder>_all.csv` / `.txt` - one pair for the whole
folder - so on its first use the file does not exist and it saves immediately.
That is the whole asymmetry the user noticed.

Reproduction, from the commander's run on a restored session:

    === このページ保存 ===
      latest_region_info = 'OCR not finished - cannot export yet'   (stale)
      dialog             = 上書き確認
        action: 'キャンセル'  autofocus=False
        action: '上書き保存'  autofocus=False

    === 全ページ保存（同じ状態） ===
      latest_region_info = 'Exported 1 regions from 1 images'
      dialog             = 保存しました
      issue_all.csv exists = True

4. THE DECISIONS THE USER MADE - DO NOT REOPEN THEM
================================================================================
[i]   No OCR data means a DIALOG, not a status line. The user's own wording
      for it is 「OCRデータがございません。」 Use that string.
[ii]  The overwrite confirmation goes away. Saving the page's own output file
      again is normal work, not a dangerous act. The output path is derived
      from the image name and cannot point at an unrelated file.
[iii] When OCR has not finished, the save is REMEMBERED and performed
      automatically once OCR completes. The user must not have to press it
      again.

After this task, `_start_export("current")` has exactly four outcomes:

    no rectangles and no mark          -> dialog 「OCRデータがございません。」
    rectangles, OCR not done, no error -> queue it, save when OCR completes
    rectangles, OCR ended in ERROR     -> dialog showing the OCR error
    otherwise                          -> write immediately, no confirmation

5. DELIVERABLES
================================================================================
[A0] A refusal is never silent - show 「OCRデータがございません。」

    Replace the "Nothing to export" early return for `scope == "current"`
    with a modal dialog:

        title    ft.Text("保存できません")
        content  ft.Text("OCRデータがございません。")
        actions  ft.TextButton("OK", autofocus=True)   -> closes it
        modal    True

    Store it in `self._save_dialog` exactly like the other dialogs, so tests
    can reach it and so `page.close` works. Keep setting
    `self.latest_region_info` as well - the status line stays informative -
    but the dialog is what the user sees.

    Do the same for the `scope == "all"` "Nothing to export" and
    "Nothing to export (N skipped: OCR not finished)" returns. The wording for
    the all-pages skipped case must say how many pages were skipped, because
    that is actionable. A silent status line is the defect being fixed; do not
    leave one behind.

    When the OCR ended in ERROR for a page that HAS rectangles, show the same
    style of dialog with the actual OCR error text as the content.

[A] Delete the overwrite confirmation

    In `_start_export`, replace the exists/else branch with an unconditional
    call:

        self._do_write_and_show_done(scope, csv_path, txt_path)

    Delete the `_show_overwrite_dialog` method entirely. It becomes dead code
    and dead code in this file has already caused one silent defect.

    This applies to BOTH scopes. `<folder>_all.csv` gets overwritten without
    confirmation too, for the same reason.

    Everything else about writing stays exactly as it is: the file names, the
    folders, the encodings (`utf-8-sig` for CSV), the row building, the mark
    rows from Task 36, and the 保存しました dialog with its 次へ / ここに残る
    / OK actions from Task 38.

[B] A save requested before OCR finishes is performed when OCR finishes

    The QUEUING applies to `scope == "current"` ONLY. The all-pages scope
    keeps refusing when pages are skipped - but as a dialog now, per [A0], not
    as a status line. Do not queue an all-pages export.

    In `_start_export`, replace the refusal at line ~856 with:

        if rects and self.ocr_state != OcrState.DONE:
            if self.ocr_state == OcrState.ERROR:
                <keep refusing - show the existing OCR error, do NOT queue>
            else:
                self._pending_export = self.image_src
                self.latest_region_info = "OCR待ち - 完了後に保存します"
                self._update_status()
                if self.page:
                    self.start_ocr(self.page)
                return

    Initialise `self._pending_export = None` in `__init__`.

    In `_on_ocr_complete` (line ~333), AFTER the existing state updates and
    AFTER the `self.image_src == target_path` block that refreshes the UI,
    add:

        if self._pending_export == target_path:
            self._pending_export = None
            if state["ocr_state"] == OcrState.DONE and self.image_src == target_path:
                self._start_export("current")

    Rules this must obey:

    - Clear `_pending_export` BEFORE calling `_start_export`, so a second
      failure cannot loop.
    - If the OCR ended in ERROR, clear the pending save and do NOT export.
      Put the OCR error in the status line.
    - If the user has moved to another page in the meantime
      (`self.image_src != target_path`), clear the pending save and do NOT
      export. Saving a page the user is no longer looking at would write a
      file they did not ask for.
    - `_switch_image` must clear `_pending_export`. Leaving a page cancels
      the queued save.
    - Pressing save twice while waiting must not queue two exports.

[C] The status line must never be stale when a save is refused or queued

    Every early return in `_start_export` already sets `latest_region_info`
    and calls `_update_status()`. Check that this is true after your change
    and that the queued case does it too. The reproduction above shows a
    stale 'OCR not finished - cannot export yet' left on screen while a
    different dialog was open; that is what made the defect look like
    "nothing happens".

[D] Nothing else changes

    No new button, no new setting, no change to the persistence from Task 39,
    no change to the 保存しました dialog, no change to Ctrl+S itself.
