================================================================================
1. WHAT CHANGES
================================================================================
Task 31 made the TXT export a flat line joined with U+FF5C (｜), and put the
image name in front only when the export covered SEVERAL images. The user asked
for that, then used it for real and changed their mind: they want the image name
on EVERY line, including a single page export, so the file always pastes into a
spreadsheet as two columns.

    NOW, exporting one page:

        人の時｜桂冠するか?押し切るか?｜靜かに「非常時」を眺める沈默の人牧野内大臣｜(T生)

    WANTED:

        A案）国際寫眞新聞_028号_000008.jpg<TAB>人の時｜桂冠するか?押し切るか?｜靜かに…

The several-images form is ALREADY "<name><TAB><joined>" per line and does not
change. So the change is simply: stop special casing the single image.

================================================================================
2. SPECIFICATION
================================================================================
In `rows_to_txt_text` in custom_gui/exporter.py, delete the branch that returns
the bare joined string when `len(images_order) == 1`. Every image, always, emits

    <image_name>\t<segment｜segment｜segment>

one line per image, in the order the image names first appear in `rows`, with a
single TAB (U+0009) between the name and the text, and a single trailing newline
at the end of the file.

Everything else that Task 31 established stays exactly as it is:

    - the separator is U+FF5C (｜), not ASCII "|"
    - empty and whitespace-only segments are dropped, so separators never double
    - newlines inside a row's text ("\n" and "\r\n") become separators, so each
      image is always exactly one line
    - an image whose segments are all empty produces NO line at all - not a
      blank one, and not a line with just the name and a tab
    - `rows` empty, or every segment empty, returns "" - not a lone newline
    - `image_name` in the rows is already a basename; use it as it is
    - `rows_to_csv_text` does not change
