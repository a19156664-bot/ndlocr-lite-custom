================================================================================
1. WHAT THE USER ASKED FOR
================================================================================
The TXT export currently writes a header block per region:

    === A案）国際寫眞新聞_028号_000009.jpg / Region 1 ===
    印棉不買からシムラ會商まで

    === A案）国際寫眞新聞_028号_000009.jpg / Region 4 ===
    南千壽

    === A案）国際寫眞新聞_028号_000009.jpg / Region 5 ===
    ―寫眞はカルナジタ・ハリソン街の綿糸布市場―

The user wants one flat line instead, with the regions joined by the FULLWIDTH
VERTICAL LINE character U+FF5C (｜), no headers and no image name:

    印棉不買からシムラ會商まで｜南千壽｜―寫眞はカルナジタ・ハリソン街の綿糸布市場―

No separator at the start, none at the end.

The CSV export does NOT change. It is the structured format and stays exactly
as it is, columns and all.

================================================================================
2. EXACT SPECIFICATION
================================================================================
Rewrite `rows_to_txt_text(rows)` in custom_gui/exporter.py. Its signature does
not change, so no caller needs editing.

SEP = "｜"   # ｜ FULLWIDTH VERTICAL LINE. Not "|" (U+007C).

2.1 Segments

    Each row contributes its `text`. Before use:
      - strip leading and trailing whitespace
      - replace every newline inside the text with SEP, so one row whose OCR
        found three lines contributes three segments and the result is
        guaranteed to be a single line. `assemble_text` joins OCR lines with
        "\n", and a user's F2 edit may contain newlines too, so this case is
        real and must be handled. Handle "\r\n" as well as "\n".
      - after that, drop any segment that is empty or whitespace only, so a
        rectangle that found no text produces nothing and the separators never
        double up.

    Do not escape or alter a SEP character that already appears in the text.
    TXT is not a structured format and the user did not ask for escaping.

2.2 One image - the common case

    When every row shares the same `image_name`, the output is exactly the
    joined segments plus a single trailing newline:

        seg1｜seg2｜seg3\n

    No image name, no header, no blank lines.

2.3 Several images - the "All images" export

    When the rows cover more than one distinct `image_name`, emit ONE LINE PER
    IMAGE, in the order the image names first appear in `rows`:

        <image_name>\t<seg1｜seg2｜seg3>
        <image_name>\t<seg1｜seg2>

    A single TAB (U+0009) between the name and the text. The user's stated
    reason: the name and the text land in separate columns when the file is
    pasted into a spreadsheet.

    `image_name` is already a basename in the rows - use it as it is.

    An image whose segments are all empty contributes NO line at all - not a
    blank one, and not a line with just the name and a tab.

    End the file with a single trailing newline.

2.4 Nothing to export

    If `rows` is empty, or every segment is empty, return "" - an empty string,
    not a lone newline. That matches today's behaviour for empty input.

================================================================================
3. DEFINITION OF DONE
================================================================================
[1] A single-image export is one line of segments joined by U+FF5C, with no
    image name, no header, no leading or trailing separator.
[2] A multi-image export is one line per image, "<name>\t<joined>", in first
    appearance order, skipping images with no text.
[3] Rows with empty or whitespace-only text are skipped and never produce
    doubled separators.
[4] Newlines inside a row's text become separators, so the output for one image
    is always exactly one line.
[5] `rows_to_csv_text` is untouched and its output is byte-identical to today.
[6] `python -m pytest tests/ -v` passes completely.
