Task 26: [NEW] Open PDFs - single page, multi page, and folders containing them

You MUST read AGENTS.md at the repository root and follow its rules.

--------------------------------------------------------------------------------
1. PURPOSE
--------------------------------------------------------------------------------
The user scans historical Japanese magazines. Their material arrives as PDFs as
well as loose image files. Today the application only accepts
.jpg/.jpeg/.png/.tif/.tiff, so PDFs cannot be opened at all.

Required, all three cases:
    - a single-page PDF
    - a multi-page PDF
    - a folder containing PDFs and/or image files, mixed

--------------------------------------------------------------------------------
2. THE ARCHITECTURE - DECIDED BY THE COMMANDER. DO NOT REDESIGN.
--------------------------------------------------------------------------------
Rasterise each PDF page to a PNG, then feed those PNGs into the EXISTING image
pipeline. Everything downstream - ImageSequence, rectangle selection, the OCR
bridge, per-image state, highlights, export - then works unchanged, and the
displayed image is byte-for-byte the image the OCR ran on, so coordinates cannot
drift.

DO NOT use the upstream `src/ocr.py --sourcepdf` path. The commander checked it:
`process_pdf_documents` renders pages internally for OCR but does NOT save the
rendered images, so the GUI would still have to render them again for display,
and a second JSON parsing path would be needed. That is duplicated work and a
coordinate-mismatch risk. Ignore that flag entirely.

RENDER LAZILY. Do not rasterise a whole PDF up front - a 200 page magazine at 300
DPI would freeze the application for a long time. Instead:
    1. When a PDF is opened, only COUNT its pages and compute the list of PNG
       paths that WILL exist. Counting is cheap.
    2. Render a page to PNG only when that page is actually about to be shown.
    3. If the PNG already exists, reuse it - never render the same page twice.

Rendering, as used by upstream src/ocr.py (copy this approach):

        import pypdfium2
        doc = pypdfium2.PdfDocument(str(pdf_path))
        page_count = len(doc)
        scale = DPI / 72.0
        pages = doc.render(pypdfium2.PdfBitmap.to_pil,
                           page_indices=[page_index],
                           scale=scale)
        pil_image = next(iter(pages)).convert("RGB")
        pil_image.save(png_path)
        doc.close()

RESOLUTION: 300 DPI, FIXED. The human owner chose this because early-Showa
magazine body text is small and 150 DPI breaks it. Define it as a module-level
constant, for example `RENDER_DPI = 300`. Do not add a UI control for it.

5. DEFINITION OF DONE
--------------------------------------------------------------------------------
[A] New module `custom_gui/pdf_loader.py`. It must NOT import flet.

        RENDER_DPI = 300
        PDF_EXTENSIONS = (".pdf",)

        def list_pdfs_in_folder(folder) -> List[str]
            # PDFs DIRECTLY inside folder, case-insensitive (.PDF counts),
            # sorted by file name, NO recursion, [] when none

        def plan_pdf_pages(pdf_path, cache_dir) -> List[Tuple[str, str, int]]
            # Opens the PDF ONLY to count pages. Renders NOTHING.
            # Returns, for each page, (png_path, pdf_path, page_index).
            # png_path must live under cache_dir and be named so a human can
            # trace it back, for example  <pdf stem>_p0003.png  (1-based page
            # number, zero padded to 4). This name becomes the image_name column
            # in the CSV export, so traceability depends on it.

        def ensure_page_rendered(png_path, pdf_path, page_index) -> str
            # Renders that single page at RENDER_DPI and writes png_path,
            # ONLY if png_path does not already exist. Returns png_path.
            # Creates parent directories as needed.

        def build_source_list(folder, cache_dir) -> Tuple[List[str], Dict[str, Tuple[str, int]]]
            # Combines images and PDFs found in `folder` into ONE ordered list
            # of displayable paths, plus a registry mapping
            #     png_path -> (pdf_path, page_index)
            # for the PDF-derived entries only.
            #
            # ORDER, and you must document and test it:
            #   sort ALL SOURCE FILES by file name, case-insensitively;
            #   an image contributes itself;
            #   a PDF contributes all of its pages, in page order, consecutively.
            # So a folder with  b.jpg, a.pdf(3 pages), c.png  yields
            #   a_p0001.png, a_p0002.png, a_p0003.png, b.jpg, c.png

[G] Failures must not crash the application.

    - A PDF with zero pages: contributes no entries; do not raise.
    - A render failure on one page must not kill navigation: report it and keep
      the application usable.

      (e) `list_pdfs_in_folder` on a folder containing a.pdf, B.PDF, notes.txt
