================================================================================
1. WHY
================================================================================
Today the application OCRs a page lazily, the first time you look at it. The
commander measured the real cost on this machine:

    model load ............. ~35.0 s   (paid EVERY time src/ocr.py starts)
    actual OCR ............. ~ 8.5 s   (per 2048x1446 image)
    -> ~43.5 s per page, every page, every session

Running src/ocr.py ONCE over a whole directory pays the 35 s only once:

    164 pages, lazily ...... 164 x 43.5 s = ~119 min, and again next session
    164 pages, batched ..... 35 s + 164 x 8.5 s = ~24 min, once, then cached

The commander verified that `--sourcedir` and `--sourceimg` produce BYTE
IDENTICAL text, bounding boxes and confidence values. Batching does not change
OCR quality. Do not attempt to prove or disprove this; it is settled.

So: run the OCR for a whole folder in one process, store the normalised result
per image on disk, and let the viewer read it back instantly.

3. FACTS ABOUT src/ocr.py - VERIFIED BY THE COMMANDER, USE THEM
================================================================================
3.1 The command to run

    <python> src/ocr.py --sourcedir <DIR> --output <OUTDIR> --json-only

    --sourcedir globs EVERY file directly inside DIR and OCRs each supported
                image. It does not recurse.
    --json-only suppresses the .xml and .txt files. Use it. We only need JSON.
    --viz       defaults to False. Do not pass it. It would write viz_*.png.

3.2 What it writes, and WHEN

    For each input image <stem>.<ext> it writes <OUTDIR>/<stem>.json, and it
    writes that file AS SOON AS THAT IMAGE FINISHES - inside the loop, not at
    the end. Two consequences you must exploit:

      * PROGRESS can be measured by counting *.json files in OUTDIR.
      * CANCELLING is not destructive: whatever finished is already on disk and
        must be harvested into the cache.

3.3 The per-image JSON shape

    {
      "contents": [ [ {line}, {line}, ... ] ],      <- list of ONE list
      "imginfo": {"img_width":..., "img_height":...,
                  "img_path":..., "img_name":...}
    }

    and each {line} is

    {"boundingBox": [[xmin,ymin],[xmin,ymax],[xmax,ymin],[xmax,ymax]],
     "id": 0, "isVertical": "true"|"false", "text": "...",
     "isTextline": "true", "confidence": 0.97, "class_index": 1}

    This is EXACTLY the shape custom_gui/ocr_bridge.py already parses.

3.4 What you must NOT use

    --sourcepdf renders at --pdf-render-dpi, default 150.0, while this project
    displays PDF pages at 300 DPI (pdf_loader.RENDER_DPI). Its bounding boxes
    would be off by a factor of two, and its JSON has a different nested shape.
    Never call it.

4. DELIVERABLE 1 - custom_gui/ocr_cache.py   (NEW FILE)
================================================================================
Pure module. No flet import. No subprocess. No GUI. Standard library only.

    CACHE_DIR_NAME = ".ndlocr_cache"
    SCHEMA_VERSION = 1

    cache_dir_for(source_path) -> str
        The directory that holds the cache for this source file:
        <folder of source_path>/.ndlocr_cache
        Returns the path. Does NOT create it.

    cache_path_for(source_path, page_index=None) -> str
        page_index is None -> <cache dir>/<stem>.json
        page_index is int  -> <cache dir>/<stem>_p{page_index+1:04}.json
        So page_index=0 gives <stem>_p0001.json. This matches the PNG naming
        pdf_loader already uses, so the later PDF task lines up for free.

    save_cache(source_path, results, page_index=None) -> str
        Creates the cache directory if needed and writes:
        {"schema": SCHEMA_VERSION,
         "source_name": <basename of source_path>,
         "source_size": <st_size of source_path>,
         "source_mtime": <st_mtime of source_path>,
         "page_index": page_index,
         "results": results}
        Written UTF-8, ensure_ascii=False. Returns the path written.
        Write to a temporary file in the same directory and os.replace() it into
        position, so a crash or a cancel mid-write can never leave a truncated
        JSON file behind.

    load_cache(source_path, page_index=None) -> Optional[list]
        Returns the results list, or None. Return None - never raise - when:
          the cache file does not exist
          the source file does not exist
          the JSON is corrupt or not a dict
          "schema" != SCHEMA_VERSION
          source_size or source_mtime no longer match the file on disk (STALE)
        On success each entry's "bbox" MUST be returned as a TUPLE of four
        floats, matching what run_ocr_and_parse returns in memory. JSON has no
        tuples, so you must convert on load. Existing code unpacks these.

    is_cached(source_path, page_index=None) -> bool
        True only if load_cache would return a list. Do not duplicate the
        validation logic - reuse it.

The stored entries are exactly the dicts run_ocr_and_parse already returns:
    {"text": str, "bbox": (x1,y1,x2,y2), "confidence": float,
     "is_vertical": bool, "source_image": str}

STALENESS NOTE: mtime is a float and JSON round-trips it. Compare with a small
tolerance (1e-6) rather than ==, so a value that survived a JSON round trip is
not judged stale.

5. DELIVERABLE 2 - custom_gui/batch_ocr.py   (NEW FILE)
================================================================================
Pure module. No flet import. It may import ocr_cache and ocr_bridge. It must
never import custom_gui/app.py.

    plan_batch(image_paths) -> (to_ocr, already_cached)
        Splits the list using ocr_cache.is_cached. Preserves input order.
        Returns two lists of paths. Does no work.

    run_batch(image_paths, progress=None, should_cancel=None, python_exe=None)
            -> BatchResult

        BatchResult carries at least:
            ok           list of paths successfully cached
            skipped      list of paths that were already cached
            failed       list of (path, reason)
            cancelled    bool

        Sequence:

        [1] plan_batch. If nothing to do, return immediately with cancelled
            False. Do not start a subprocess.

        [2] Reject duplicate basenames among the paths to OCR. src/ocr.py names
            its output <stem>.json, so two files with the same basename from
            different folders would silently overwrite each other. Detect this
            and put every colliding path into `failed` with a clear reason
            rather than producing wrong results.

        [3] Build a staging directory (tempfile.mkdtemp) containing one entry
            per image to OCR. Try os.link() first - a hard link costs no disk
            and no copy. If os.link raises for ANY reason (different volume,
            filesystem without hard links, permissions), fall back to
            shutil.copy2 for that file. Both must work; test both paths.
            Reason: --sourcedir OCRs everything in the directory it is given, so
            we cannot point it at the user's folder when only some pages need
            work - a resume after cancel would redo everything.

        [4] Run src/ocr.py ONCE over the staging directory with subprocess.Popen
            (not subprocess.run - you must be able to poll and to kill it),
            writing into a separate temporary output directory, with
            --json-only.
            Use python_exe if given, otherwise sys.executable. Run it with the
            repository root as cwd, exactly as ocr_bridge.py does.

        [5] While it runs, poll about once a second:
              - count the *.json files in the output directory and, if the
                count changed, call progress(done, total) if progress is given.
                progress must never be called from inside the polling sleep
                more often than the count actually changes.
              - if should_cancel is given and should_cancel() returns True,
                terminate the process: proc.terminate(), wait briefly, then
                proc.kill() if it is still alive. Set cancelled True and go to
                [6] anyway. DO NOT throw away completed work.

        [6] Harvest. For every image that was to be OCR'd, look for its
            <stem>.json in the output directory:
              present -> parse it with the shared parser from ocr_bridge (see
                         Deliverable 3), save_cache it against the ORIGINAL
                         source path, append to ok
              absent  -> append to failed with a reason. If we cancelled, the
                         reason must say so; a page that was simply never
                         reached is not a defect.

        [7] Always delete both temporary directories, even on exception or
            cancel. Use try/finally. Never delete anything the user owns.

        A non-zero exit code from src/ocr.py when we did NOT cancel is a
        failure: record stderr in the reason for the images that produced no
        JSON. Do not raise out of run_batch for that - the caller is a GUI and
        must stay alive. Only genuinely programmer-level errors may propagate.
