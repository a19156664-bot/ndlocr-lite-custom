================================================================================
Task 48: Make 「マーク読取」 also record 【広告】 from the orange mark
================================================================================

## 1. Purpose and background

The user marks scanned pages by hand in two colours. AGENTS.md section 8.1
records what the approver decided they mean:

    cyan   -> an area to OCR          -> detect_marks()      (Task 45, merged)
    orange -> THIS PAGE IS AN ADVERT  -> detect_page_mark()  (Task 47, merged)

Task 46 shipped the 「マーク読取」 button, which uses `detect_marks` only.
This task makes that same button also act on the orange mark, so one press
does everything the page's marks ask for.

Both functions are on master already:

    from custom_gui.mark_detector import load_image, detect_marks, detect_page_mark

    detect_page_mark(image_bgr, min_area: int = 2000) -> Optional[str]
        returns page_marks.MARK_AD ("【広告】") or None

Recording an advert is ALREADY implemented, in `_on_mark_click(MARK_AD)`.
It sets `self.mark`, updates `self.image_states[self.image_src]["mark"]`,
persists the work state, and appends a line to the page's .txt via
`append_mark_line`, which returns False when the line is already there.

**Call the existing handler. Do not write a second copy of that logic, and do
not write the string "【広告】" anywhere.** One vocabulary, one code path.

## 2. THE POINT OF THIS TASK — read this before you write anything

`_on_marks_to_rects_click` currently returns early:

        regions = detect_marks(img)

        if not regions:
            self.latest_region_info = "マークが見つかりません"
            self._update_status()
            return

**Measured on the 52 real pages (2026-08-27): 8 of the 9 advert pages carry NO
cyan mark at all** (`000002` `000003` `000004` `000005` `000006` `000050`
`000051` `000052`). Only `000048` carries both.

So if you leave that early return where it is, the feature does nothing on
8 of the 9 pages it exists for.

**The orange mark must be handled BEFORE the empty-regions check.**

## 3. Definition of Done (verifiable)

Rewrite the body of `_on_marks_to_rects_click` in `custom_gui/app.py` to this
order. Everything else in the method stays as it is.

    1. Load the image. Keep the existing try/except exactly as it is:
       on FileNotFoundError, ValueError or OSError set self.latest_region_info
       to a message containing "読み込めません", call self._update_status(),
       and return. The handler must never raise.

    2. page_mark = detect_page_mark(img)
       If page_mark is not None:
           call self._on_mark_click(page_mark)
           and remember that you did, in a local flag.
       If page_mark is None:
           do NOTHING to the page's mark. **A 【広告】 or 【表紙】 the user set
           by hand must survive this button untouched.** Never clear a mark.

    3. regions = detect_marks(img)

    4. Add the regions exactly as the method does today, including the
       duplicate check within 2 pixels on all four sides (Task 46, DoD-3).

    5. Set self.latest_region_info LAST, after step 2, because
       `_on_mark_click` writes to `self.latest_region_info` itself and would
       otherwise overwrite your message. The message must state both outcomes:

           regions added and advert recorded:
               マークから 3 個の矩形を作りました（囲み 3・傍線 0）／【広告】として記録しました
           advert only, no cyan at all:
               【広告】として記録しました（矩形のマークはありません）
           regions only:
               マークから 10 個の矩形を作りました（囲み 1・傍線 9）
           neither:
               マークが見つかりません

       The exact wording is yours; the four cases must be distinguishable.
       Build the 【広告】 half of the message from the value `_on_mark_click`
       was given, not from a literal.

    6. Call self._update_selections_ui() and self._persist_work_state() as the
       method does today, in the same place. Skip neither, even when only the
       advert was recorded.

**Do not start OCR. Do not open the inline editor. Do not change the mode.
Do not spawn a thread.**

**Locking:** `_update_selections_ui`, `_persist_work_state` and
`_on_mark_click` all take `self.selections_lock` or call something that does.
Do not hold the lock while calling any of them. Never remove or weaken a
`with self.selections_lock:` block - that was the serious defect of Task 30c.
