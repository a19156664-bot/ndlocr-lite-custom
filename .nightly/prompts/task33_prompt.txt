1. WHAT THE USER ASKED FOR
================================================================================
"OCRの枠をselectした場合に、右枠に表示する前にselect枠付近にテキスト表示する
 および編集を可能とする、エンターで右枠に移動。

Proof-reading today means: draw a rectangle on the image, then move your eyes
and your mouse to the panel on the right to read and correct the text. The user
wants to correct it where they are looking - next to the rectangle.

The commander asked the user to settle two points. Their answers:

    WHEN DOES IT OPEN?  On drawing a NEW rectangle, AND on clicking an EXISTING
                        rectangle on the image. Both.
    WHAT IF IT IS CLOSED WITHOUT Enter?
                        The rectangle stays. Only the edit is discarded.

================================================================================
2. THE FLOW
================================================================================
    draw a rectangle          -> an editor appears next to it, holding the OCR
                                 text for that region, focused
    click an existing rectangle -> same, holding that region's current text
                                 (the edited text if it has been edited)
    Enter                     -> the text is saved and the editor closes; the
                                 right hand panel shows it, with "(edited)" if
                                 it differs from the OCR text
    Shift+Enter               -> inserts a line break, does NOT close
    Escape, or clicking away  -> the editor closes, the edit is DISCARDED, and
                                 the rectangle and its OCR text remain

================================================================================
3. FOUR TRAPS THE COMMANDER FOUND IN THE CODE - HEED THEM
================================================================================
3.1 DO NOT put the editor in `rects_layer`.

    `_update_selections_ui` begins with

        self.rects_layer.controls.clear()
        self.highlight_layer.controls.clear()
        self.selections_list.controls.clear()

    and it is called whenever OCR finishes, a page is switched, a region is
    deleted, and more. An editor living in `rects_layer` would be destroyed
    mid-typing, losing the user's text and the keyboard focus.

    Add a SEPARATE layer, for example `self.inline_editor_layer = ft.Stack(...)`,
    which `_update_selections_ui` NEVER clears.

3.2 The new layer must sit ABOVE the gesture detector.

    The stack is built as

        ft.Stack(controls=[image_control, highlight_layer, rects_layer,
                           gesture_detector])

    `gesture_detector` is on top and swallows pointer events. A TextField
    underneath it cannot be clicked or typed into. Put the editor layer AFTER
    gesture_detector.

    The stack is constructed in THREE places in custom_gui/app.py - around lines
    209, 220 and 637. Update all three, or the editor will silently vanish after
    a page switch. Find them with `grep -n "ft.Stack(controls=\[self.image_control"`.

3.3 Escape is currently swallowed.

    In `main()`:

        def on_keyboard(e: ft.KeyboardEvent):
            if viewer.editing_region_id is not None:
                # Suppress global shortcuts while editing text
                return

    Escape must reach your handler while the inline editor is open, while
    Ctrl+N and F2 stay suppressed - typing an "N" must never turn the page.
    Extend that guard rather than removing it.

3.4 Everything that mutates a layer must hold the lock.

    Task 30c added `self.selections_lock` (an RLock) because flet dispatches
    every non-async event handler on a thread pool WITHOUT serialising them, and
    concurrent rebuilds corrupted the control tree. Opening and closing the
    editor mutates `inline_editor_layer.controls`, so it must hold the same
    lock. Do not add a second lock - use `self.selections_lock`.

4. DELIVERABLES
================================================================================
[A] The editor layer.

    `self.inline_editor_layer`, a ft.Stack, above the gesture detector in all
    three stack constructions, carrying the pan offset exactly as
    `rects_layer` does - set its `.left` / `.top` to `self.offset_x` /
    `self.offset_y` wherever `rects_layer`'s are set, so it pans with the image.
    `_update_selections_ui` must not clear it.

[B] Opening it.

    New attribute `self.inline_editing_region_id`, None when closed.

    B1. After `_on_pan_end` adds a new rectangle in SELECT mode, open the editor
        for it. Note the existing zero-area guard - a rectangle that was not
        added must not open an editor.
    B2. Add `on_tap` to the gesture detector. On a tap, convert the tap point to
        original image coordinates and find the topmost existing rectangle
        containing it; if there is one, open the editor for it and make it the
        active region. A tap on empty space closes any open editor (discarding
        the edit) and does nothing else. A tap produces a zero-area bbox, which
        the existing guard already discards - do not break that.

    The editor holds the region's current text: the edited text if the region
    has one in `self.edits`, otherwise the assembled OCR text - the same string
    the right hand panel would show.

    Position it NEXT TO the rectangle, not on top of it - the user is reading
    the image underneath. Below the rectangle is the natural place; fall back to
    above when there is no room below. Clamp it so it stays inside the visible
    area. Reuse `calculate_label_position` from custom_gui/viewer.py if it
    helps, but DO NOT MODIFY that function.

    Set `autofocus=True` so the user can type immediately.

[C] Committing.

    `multiline=True, shift_enter=True, on_submit=...` - the same pattern Task 32
    used in the right hand panel. On submit: store the text in `self.edits[rid]`,
    clear `self.inline_editing_region_id`, remove the editor, and refresh the
    panel so the region shows the new text with its "(edited)" suffix and a
    Revert button.

    Route this through the SAME code path the right hand panel uses to commit,
    so the two can never drift apart.

[D] Cancelling keeps the rectangle.

    Escape, or `on_blur`, closes the editor and discards what was typed.
    `self.edits` must be left exactly as it was - if the region had no edit it
    still has none; if it had an earlier edit that earlier edit survives. The
    rectangle, its OCR text, its highlights and its entry in the right hand
    panel all remain.

[E] Do not break the right hand panel.

    F2 still opens the panel editor, its save button and Enter still work, and
    Revert still works. The two editors must not be open for the same region at
    once - opening one closes the other.
