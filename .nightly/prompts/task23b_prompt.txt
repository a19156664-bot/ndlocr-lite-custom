PART 1 - THE CRASH
--------------------------------------------------------------------------------
1.1 REPRODUCED BY THE COMMANDER. DO NOT RE-INVESTIGATE.

If the application starts with an image path that does NOT exist, and the user
then opens a folder, the application raises:

        AttributeError: 'SelectableImageViewer' object has no attribute 'stack'

1.2 ROOT CAUSE - ALREADY DIAGNOSED.

In `SelectableImageViewer.__init__`, `self.stack` is created ONLY in the healthy
branch:

        if self.ocr_error:
            self.image_container.content = ft.Text(self.ocr_error, ...)
        else:
            self.stack = ft.Stack(controls=[self.image_control,
                                            self.highlight_layer,
                                            self.rects_layer,
                                            self.gesture_detector], ...)
            self.image_container.content = self.stack

When the start-up image is missing, `ocr_error` is set, so `self.stack` is never
assigned. Later, `_switch_image()` unconditionally does:

            self.image_container.content = self.stack

and raises. The user can therefore never recover from a bad start-up path by
opening a good folder - the only escape is to restart the application.

1.3 DEFINITION OF DONE - PART 1

    Build it unconditionally. Keep showing the red error Text in
    `image_container` when there is an error - only the CREATION of the Stack
    moves out of the else branch. Do not change what the user sees in the error
    state.

[B] Recovery must work.
    Starting with a missing image and then opening a folder that contains valid
    images must switch to the first image and display it normally, with no
    exception. Going back to an image whose file is missing must show the error
    text again without crashing.

[C] A regression test that ACTUALLY FAILS on the old code.
    Add it to the new test file described in Part 2, or to a new

    In your report, PROVE BOTH DIRECTIONS: show the test FAILING against the

2.2 CURRENT CODE CONTRACT (on master - use it, do not change it)

custom_gui/exporter.py:

        #   image_name, region_id, x1, y1, x2, y2, line_count, text
        # edited_texts is {rect_id: str}; when present it replaces the OCR text,
        # while line_count keeps counting raw OCR lines.
    rows_to_csv_text(rows) -> str      # header:
                                       # image_name,region_id,x1,y1,x2,y2,line_count,text
    rows_to_txt_text(rows) -> str      # "=== <image_name> / Region <id> ===" blocks

                             "ocr_results" -> list of OCR line dicts
                             "ocr_error"   -> str or None
                             "edits"       -> {rect_id: str}
    self.selection_container, self.ocr_results, self.ocr_state
    self.export_button, self.file_picker, self._file_picker_mode
    _on_export_click(e) / _on_file_picker_result(e) / _update_status()
    self.latest_region_info    str shown after "Last:" in the status bar

    class OcrState(Enum): IDLE / RUNNING / DONE / ERROR

      (f) The TXT output contains both "=== a.jpg / Region 1 ===" and
