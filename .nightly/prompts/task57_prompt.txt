================================================================================
Task 57: After a page switch, put the image back at 0 like the box layers
================================================================================

This order is Task 57 in .nightly/ROADMAP.md (AGENTS.md section 8.10).

## 1. Purpose and background

In the check viewer, after the user drags the page in Pan mode and then goes
to another page, the new page's image is drawn shifted while the blue boxes
are drawn at the normal place. The approver saw it on issue 141 pages 11 and
12 on 2026-10-07. It also happens on code from before Task 56.

Cause (custom_gui/app.py, SelectableImageViewer):

  - _on_pan_update (PAN branch) moves self.offset_x / self.offset_y and writes
    them to self.image_control.left/top AND to highlight_layer, rects_layer
    and inline_editor_layer .left/.top. Image and layers move together.
  - _switch_image sets `self.offset_x = 0.0` and `self.offset_y = 0.0`
    (about line 854), and _update_selections_ui later writes the offsets to
    the three layers. But nothing writes them to self.image_control.left/top.
    So the image keeps the old Pan position and the layers go back to 0.

The commander measured it on master (2026-10-07, inside a pytest test, using
the harness of tests/test_persistence.py): Pan from (50,50) to (10,20), then
_switch_image to a second image:

    image_control.left/top   -40.0 / -30.0
    offset_x / offset_y        0.0 /   0.0
    rects_layer.left/top       0.0 /   0.0
    highlight_layer.left/top   0.0 /   0.0

A box drawn in this state is computed with offset 0, while the user sees the
image shifted, so it would be saved over different text. The approver decided
(2026-10-07) to fix it.
