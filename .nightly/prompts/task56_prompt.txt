================================================================================
Task 56: Give the page image to the browser as a URL, not as base64
================================================================================

## 1. Purpose and background

The approver runs the check viewer with `launch_viewer.py` (repository root,
added to git on 2026-10-07 in commit e600426; before that it was outside git).
It opens the viewer in a web browser (ft.AppView.WEB_BROWSER, port 8555).

Zoom In / Zoom Out and dragging the page in Pan mode are very slow. The
commander measured it on 2026-10-07 (issue 141 page 1, Edge, width 1920,
3 runs each, Playwright):

    Zoom In/Out (18 clicks)  the browser freezes 617-750 ms per click
    Pan, 40 mouse moves      52-56 seconds (each move freezes 1.1-1.25 s)

Cause: launch_viewer.py reads each page PNG (2253x3074, 5-12 MB) and puts it
into ft.Image as base64 (7-16 MB of text). Every time the image's position or
size changes, the browser decodes the whole picture again.

The commander tried, outside the repository, a copy of launch_viewer.py that
sets `image_control.src = "/" + <file name>` and `src_base64 = None`, and
passes `assets_dir=CACHE_DIR` to ft.app. Same measurement:

    Zoom In/Out (18 clicks)  freezes 17-114 ms
    Pan, 40 mouse moves      2.0-2.4 seconds (freezes 18-33 ms)

and the boxes still follow the image after zoom and pan. The file names
contain Japanese (e.g. 国際寫眞新聞_141号_p0001.png); the raw, NOT
percent-encoded name worked. This task makes that change properly, with tests.

## 2. Contract

### DoD-1 -- new module custom_gui/web_image.py

    import os

    def web_image_src(image_path: str, assets_dir: str) -> str:
        """URL path of image_path inside assets_dir, for ft.Image.src in the
        web viewer: "/" + the relative path with "/" separators.
        Raises ValueError if image_path is not inside assets_dir."""

    def show_web_image(image_control, image_path: str, assets_dir: str) -> None:
        """Show image_path in image_control through the URL:
        image_control.src = web_image_src(image_path, assets_dir)
        image_control.src_base64 = None"""

Rules:
- Use os.path.abspath on both arguments, then os.path.relpath; replace
  os.sep with "/". If the relative path is "." or ".." or starts with ".." + os.sep,
  or the two paths are on different drives (relpath raises ValueError),
  raise ValueError.
- Do NOT percent-encode (urllib.parse.quote). Keep the characters as they are
  (this is what was measured to work).
- show_web_image does not call update(); the caller already does.
- No other functions, no flet import needed.

### DoD-2 -- launch_viewer.py uses it (only these changes)

1. Add `from custom_gui.web_image import show_web_image` next to the other
   custom_gui imports.
2. In BrowserImageViewer._switch_image, replace the 4 lines

        b64 = encode_base64(path)
        if b64:
            self.image_control.src_base64 = b64
            self.image_control.src = None

   with

        show_web_image(self.image_control, path, CACHE_DIR)

   It must stay AFTER `super()._switch_image(path)` and AFTER the
   ensure_page_rendered call at the top of the method (the PNG of a page
   opened for the first time is drawn there; the URL must point to a file
   that exists).
3. In main(), replace the 4 lines

        b64 = encode_base64(p0)
        if b64:
            viewer.image_control.src_base64 = b64
            viewer.image_control.src = None

   with

        show_web_image(viewer.image_control, p0, CACHE_DIR)

4. The last line becomes

        ft.app(target=main, view=ft.AppView.WEB_BROWSER, port=8555, assets_dir=CACHE_DIR)

   (port and view unchanged).
5. Delete the now unused `def encode_base64(path)` and `import base64`.
6. Nothing else in launch_viewer.py changes: not BASE_DIR, not the Region 1
   auto box, not normalize_page_ocr, not the printed messages, not the window
   size, not the keyboard handler.
