## 1. Purpose and background

custom_gui/app.py, SelectableImageViewer. Each row of the right panel
(self.selections_list) is an ft.Container built in _update_selections_ui
(item = ft.Container(content=ft.Column([ft.Row([header_text,
ft.Row(buttons)]), content_area]), border=..., on_click=make_active)).

The "この枠だけOCR" button calls start_region_ocr(rid). It runs
region_ocr_text in a thread (self.page.run_thread(_run_region_ocr)). When the
thread finishes with text, it sets self.edits[rid] and calls
self._update_selections_ui(), which CLEARS and REBUILDS every row.

Two problems found by the approver on 2026-10-07:

  A. If the user is typing in ANOTHER row's edit field (editing_region_id),
     the rebuild throws that TextField away and builds a new one from the
     saved text: what the user was typing is lost and the edit looks closed.
  B. While OCR runs, the only sign is the status text "範囲OCR中…", which
     shows only the latest one. The user cannot see which rows are running.

The approver decided (2026-10-07):

  - While a row's region OCR runs, that row's Container has
    bgcolor = ft.Colors.ORANGE_100 (only the right-panel row; the blue box
    on the image does not change). The green active border stays as it is.
  - When the OCR ends in ANY way (text, no text, error, the page was
    switched, the rect was deleted), the colour goes away.
  - When it finishes with text, rebuild ONLY that row and put it in place of
    the old row object in self.selections_list.controls. The other rows stay
    the SAME objects (so a TextField being typed in survives).
  - If that same row is being edited (editing_region_id == rid) when the OCR
    finishes, do NOT apply the OCR text (protect what the user types); set
    the status to "編集中の枠なので範囲OCRの結果を入れませんでした".

## 2. Contract

### DoD-1 -- one row builder (pure extraction)

Move the body of the `for rect in all_rects:` loop of _update_selections_ui
into a new method

    def _build_row(self, rect) -> ft.Container

that returns the row Container, and make the loop call it and append the
result. The row must be built EXACTLY as today (same tree shape, same
buttons in the same order, same tooltips, same closures). Existing tests read
row.content.controls[0] as an ft.Row with exactly 2 controls
[header ft.Text, ft.Row(buttons)]; keep that. The only addition in
_build_row is DoD-2.3.

### DoD-2 -- running set and colour

1. In __init__, next to self.hidden_regions, add
       self.region_ocr_running = {}   # image path -> set of rect_id (str)
   and a helper
       def _running_ids(self, path=None):
           return self.region_ocr_running.setdefault(path or self.image_src, set())
   It is never saved to disk.
2. In start_region_ocr, after the existing early returns (edited row, rect
   not found) and before starting the thread: add str(rid) to
   self._running_ids(saved_image_src), and colour the CURRENT row object for
   rid (find it in self.selections_list.controls; see DoD-3.1) with
   bgcolor = ft.Colors.ORANGE_100 and call .update() on it if it has a page.
   Do NOT call _update_selections_ui here.
3. In _build_row: bgcolor = ft.Colors.ORANGE_100 if str(rect.rect_id) is in
   self._running_ids() else None. (So a rebuild for any other reason keeps
   the colour.)

### DoD-3 -- finishing touches only one row

1. Add
       def _row_index(self, rid) -> int | None
   that returns the index in self.selections_list.controls of the row built
   for rid. Keep a dict self._row_by_id = {rect_id: row_container} filled by
   _update_selections_ui (cleared at the start of each rebuild) and by the
   new _refresh_row; _row_index looks the object up with `is`.
2. Add
       def _refresh_row(self, rid)
   which, inside `with self.selections_lock:`, builds a new row with
   _build_row(rect) for the current rect with that id, replaces the old
   object at _row_index(rid) in self.selections_list.controls, updates
   self._row_by_id, and calls self.selections_list.update() if it has a page.
   If the rect no longer exists or no row is found, do nothing.
3. Rewrite the inner function _run_region_ocr in start_region_ocr so that:
   - everything after starting is inside try/finally; the finally removes
     str(rid) from self._running_ids(saved_image_src) (discard), and if
     self.image_src == saved_image_src it repaints that row's colour
     (find the row with _row_index; set bgcolor None; update if it has a page).
   - On success (text non-empty, rect still exists, same page):
       if self.editing_region_id == rid: do not set edits; status
         "編集中の枠なので範囲OCRの結果を入れませんでした".
       else: self.edits[rid] = text; status "範囲OCR: {n} 行" as today;
         then self._refresh_row(rid) (NOT _update_selections_ui),
         self._persist_work_state(), self._update_status().
   - "" (no text), exception, page switched, rect deleted: same messages and
     behaviour as today, except that _update_selections_ui is NOT called.
   Note the order: the colour is cleared in finally, AFTER _refresh_row, and
   _refresh_row builds the row while rid is still in the running set; so the
   finally must set bgcolor None on the NEW row object.

Nothing else changes: not commit_edit, delete_rect, rtl_rect, restore_rect,
toggle_region_visible, _redraw_overlays, the export, work_state, the eye
button, the Region 1 rules, launch_viewer.py.
