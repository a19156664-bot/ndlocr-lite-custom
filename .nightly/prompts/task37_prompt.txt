Task 37: [UX] Right-click toggles Pan, and the cursor shows which mode you are in

You MUST read AGENTS.md at the repository root and follow its rules.

Small and self contained. One new event handler and one property, wired to the

================================================================================
1. WHAT THE USER ASKED FOR
================================================================================
    "右クリックで画像を掴んで画像を動かせる機能を追加したいです。
     理由：業務効率化
     また、右クリック時やPanボタン実行時はカーソルを"手"のマークに変更する
     ことは可能でしょうか。理由：状態を可視化できるため。"

The user proof-reads page after page. Today, moving the image means travelling
to the Select/Pan toggle in the toolbar, clicking it, dragging, then travelling
back. They want to stay on the image.

================================================================================
2. WHAT IS AND IS NOT POSSIBLE - THE COMMANDER MEASURED THIS
================================================================================
Dragging with the RIGHT button held down is IMPOSSIBLE in flet 0.27.6. Do not
attempt it and do not report that you have achieved it.

ft.GestureDetector's only right-button events are

    on_secondary_tap, on_secondary_tap_down, on_secondary_tap_up,
    on_secondary_long_press_start, on_secondary_long_press_end

`on_pan_start` / `on_pan_update` / `on_pan_end` fire for the PRIMARY button
only. There is no secondary equivalent, so no movement events arrive while the
right button is held. The long-press pair does not help either - it reports the
press and the release, never the motion in between.

So the user chose this instead: a right click TOGGLES the mode, and the normal
left drag does the moving.

What IS available, verified in this project's own venv:

    ft.GestureDetector(mouse_cursor=...)        exists
    ft.MouseCursor.PRECISE / GRAB / GRABBING    all exist
    assigning gd.mouse_cursor at runtime works

ft.MouseRegion does NOT exist in 0.27.6. Do not import it.

3. THE CODE AS IT IS TODAY
================================================================================
custom_gui/viewer.py holds the mode - do NOT modify this file:

    class InteractionMode:
        def __init__(self):
            self.current = "SELECT"
        def set_mode(self, mode):
            if mode in ["SELECT", "PAN"]:
                self.current = mode

custom_gui/app.py, in SelectableImageViewer.__init__:

    self.mode_state = InteractionMode()
    self.mode_toggle = ft.SegmentedButton(
        segments=[
            ft.Segment(value="SELECT", icon=ft.Icon(ft.Icons.HIGHLIGHT_ALT), label=ft.Text("Select")),
            ft.Segment(value="PAN", icon=ft.Icon(ft.Icons.PAN_TOOL), label=ft.Text("Pan"))
        ],
        selected={self.mode_state.current},
        on_change=self._on_mode_change
    )

    self.gesture_detector = ft.GestureDetector(
        on_pan_start=self._on_pan_start,
        on_pan_update=self._on_pan_update,
        on_pan_end=self._on_pan_end,
        width=self.win_w,
        height=self.win_h,
        drag_interval=10,
    )

and `_on_mode_change` reads `e.control.selected`, calls
`self.mode_state.set_mode(...)`, refreshes the status text and updates.

`_on_pan_start`, `_on_pan_update` and `_on_pan_end` already branch on
`self.mode_state.current` being "SELECT" or "PAN". Do not restructure them.

4. DELIVERABLES
================================================================================
[A] Right click on the image toggles the mode

    Add `on_secondary_tap` to `self.gesture_detector`, pointing at a new
    method `self._toggle_mode`. It must:

        - flip "SELECT" <-> "PAN" through `self.mode_state.set_mode`,
        - keep the toolbar SegmentedButton in step:
              self.mode_toggle.selected = {self.mode_state.current}
        - refresh the cursor per [B],
        - refresh the status line, which already prints "Mode: SELECT" /
          "Mode: PAN", so the user sees the change in two places,
        - update only what is needed, guarded the way the rest of the file
          guards it (`if self.page:`).

    Do NOT add on_secondary_tap_down or on_secondary_tap_up. One handler.

    Toggling must not disturb anything else: it must not clear selections,
    must not cancel an OCR, must not close the inline editor, must not change
    the zoom, and must not move the image.

[B] The cursor shows the mode

    A single method, `self._refresh_cursor()`, sets
    `self.gesture_detector.mouse_cursor`:

        mode is "SELECT"                 -> ft.MouseCursor.PRECISE
        mode is "PAN", not dragging      -> ft.MouseCursor.GRAB
        mode is "PAN", dragging right now-> ft.MouseCursor.GRABBING

    Call it from `__init__` (so the very first cursor is right), from
    `_toggle_mode`, from `_on_mode_change` (so the toolbar button changes the
    cursor too), and from `_on_pan_start` / `_on_pan_end` for the GRABBING
    state.

    Track the drag with a plain boolean, e.g. `self._is_dragging`, set True in
    `_on_pan_start` and False in `_on_pan_end`, initialised False in
    `__init__`. Do NOT name it `self.dragging` if that collides with anything
    in flet - check before you choose.

    `_on_pan_start` and `_on_pan_end` fire in SELECT mode as well, when the
    user is drawing a rectangle. In SELECT mode the cursor must stay PRECISE
    throughout - do not let a rectangle drag turn the cursor into GRABBING.

[C] Nothing else about panning changes

    The offset arithmetic, the layers carrying the offset, the offset
    subtraction in `_on_pan_start`/`_on_pan_update`, and the rectangle drawing
    all stay byte-for-byte as they are. This task adds a trigger and a cursor;
    it does not touch how panning works.
