================================================================================
1. [A] THE REGRESSION - the live drag rectangle is double-offset
================================================================================
Task 30c made `highlight_layer` and `rects_layer` carry the pan offset on their
own `.left` / `.top`, so their children are positioned with
`original_to_display(..., 0.0, 0.0)`.

`_on_pan_start` was not updated. It still does:

        self.active_rect = ft.Container(left=e.local_x, top=e.local_y, ...)
        self.rects_layer.controls.append(self.active_rect)

`e.local_x` is already in on-screen coordinates, but the rectangle now sits
inside a layer that adds the offset again.

Measured by the commander on the real widget tree:

        pan the image by (120, 80)
        start a SELECT drag at the mouse position (300, 300)
        -> the red preview rectangle renders at (420, 380)
        release -> the committed rectangle lands correctly at (300, 300)

So the preview follows the mouse at the wrong place whenever the image has been
panned. Only the preview is wrong; the stored bbox and the OCR results are
correct.

Fix `_on_pan_start` and `_on_pan_update` so the preview is drawn in the layer's
own coordinate space - subtract the offset the layer already applies. Do not
change `calculate_normalized_bbox`, and do not change the committed geometry:
after your fix a rectangle drawn from (300, 300) to (700, 650) while panned by
(120, 80) must still produce the SAME bbox it produces today.

================================================================================

[B] Count the whole folder.

    Progress must be expressed over every page the batch was asked about, with
    already-cached pages counted as done:

        done  = len(already_cached) + <finished so far>

    So it starts at 2/52 and ends at 52/52. Do this in the viewer. Do NOT modify

[C] A visible progress bar.

    Add an ft.ProgressBar across the top of the viewer area, above the image.
    visible=False normally, visible only while a batch runs, with
    value = done / total as a float 0.0-1.0. It must not disturb the layout when
    hidden and must not change the image geometry: zoom_scale must stay 0.2605
    for a 2218x3071 image in a 1600x900 window.

[D] Spin the ring, and estimate the time left.

    self.progress_ring.visible must be True while a batch runs.

    Estimate from what actually happened - do not hard code a per page constant:

        per_page  = (now - batch_start) / pages_finished_this_run
        remaining = per_page * pages_left

    Show nothing until at least one page has finished this run; there is no
    honest estimate before that. Format for a human - "about 8 min",
    "about 40 sec". Round it.

[E] Label the button.

    Replace the ft.IconButton with a labelled control in the same toolbar
    position, third, right after Open PDF. Zoom In / Zoom Out / Fit are already
    text buttons. Keep the attribute name self.btn_batch_ocr.

        idle    : text "Pre-OCR All"   tooltip explaining PDF pages are skipped
        running : text "Cancel"        tooltip "Cancel pre-OCR"

[F] Wait for an in-flight lazy OCR before starting the batch.

    `start_ocr` already returns early once self.batch_running is set, so nothing
    NEW starts, but a job already running keeps going and both processes load
    the model on a 4 core machine. On click, if a lazy OCR is RUNNING, set
    batch_running immediately, show "Cancel", and wait for that job to finish ON
    THE WORKER THREAD before launching run_batch. Report it in the status, for
    example "Pre-OCR: waiting for the current page...". Cancelling during the
    wait must abort without launching the batch.

    cache file can short circuit the cache-first path in a later run, making a
    lazy-OCR test pass for the wrong reason.

    G1. Add `.ndlocr_cache/` to .gitignore.
    G2. Make the tests that OCR the bundled image work on a COPY under pytest's
        tmp_path. You MAY edit these existing test files FOR THIS PURPOSE ONLY:

            tests/test_async_ocr.py
            tests/test_layout_stability.py
            tests/test_missing_image_recovery.py
            tests/test_flet_constants.py

        The ONLY permitted change is where the image comes from - copy it into
        tmp_path with shutil.copy2 and point the test at the copy. NOT ONE
        ASSERTION MAY CHANGE. No test may be relaxed, skipped, renamed or
        deleted. If making a test work on a copy would require changing an
        assertion, STOP and report it instead.

        Prove it: delete resource/.ndlocr_cache, run the full suite, and show
