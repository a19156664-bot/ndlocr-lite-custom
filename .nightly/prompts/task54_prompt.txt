## 1. Purpose and background

The approver checked issue 141 in the viewer on 2026-10-04 and found four
problems. The commander read the code; the causes are below. The approver
approved this plan on 2026-10-04.

(A) Zoom In / Zoom Out / Fit move the image but not the boxes.
    Boxes are kept in ORIGINAL pixels (SelectionRect.bbox) and converted with
    original_to_display(x, y, self.zoom_scale, 0.0, 0.0) only inside
    _update_selections_ui (app.py around lines 1338-1387). zoom_in / zoom_out /
    fit (custom_gui/viewer.py lines 101-114) change self.zoom_scale and call
    self._update_viewer(). The override SelectableImageViewer._update_viewer
    (app.py around line 1639) resizes the layers but never redraws the boxes,
    so they stay where the OLD scale put them. page resize
    (update_layout -> _update_viewer) has the same problem.

(B) The automatic "Region 1" covers the whole page, so every OCR line on the
    page is painted with the 40 % yellow line highlight (app.py lines
    1374-1387). The approver's hand-drawn yellow-green marks cannot be seen
    under it. The approver decided: KEEP the Region 1 box, its label and its
    text in the right panel; only do NOT paint line highlights for Region 1.
    Region 1 is the region whose rect_id is "1" -- the same rule that
    custom_gui/form_export.py already uses (`r["region_id"] != "1"`).

(C) In the right panel (ListView width=300, app.py line 219-224) every row puts
    the bold header text and 4-5 IconButtons in ONE Row, so the last button is
    cut off at the right edge. The approver decided: keep the width 300; the
    buttons go to the line under the header.

(D) While a region's text is being edited in the right panel, the approver
    wants to SEE every line break in red, to delete the extra breaks the OCR
    produced, and wants the "[改行 N]" count in the header to change while
    typing. flet 0.27.6 TextField cannot color part of its text, so the
    approver chose: put a visible red mark character in front of each line
    break inside the edit field, and remove every mark when saving. The mark
    must NEVER reach self.edits, the saved work state, or the export.

## 2. Contract

### DoD-1 -- new file `custom_gui/break_marks.py`

    BREAK_MARK = "\U0001F534"     # the red circle emoji; the ONLY place it is written

    def add_break_marks(text) -> str:
        """None or "" -> "". Replace "\r\n" with "\n", then put BREAK_MARK in
        front of every "\n"."""

    def strip_break_marks(text) -> str:
        """None or "" -> "". Remove EVERY BREAK_MARK (also ones that are no
        longer in front of a "\n" because the user deleted the break).
        Nothing else changes."""

Write the emoji in break_marks.py with the escape "\U0001F534", not as a
literal character.

### DoD-2 -- `custom_gui/app.py`: redraw the boxes when the scale changes (A)

1. Add a method `_redraw_overlays(self)` to SelectableImageViewer. It does
   exactly what _update_selections_ui does today for the IMAGE side, moved
   out unchanged: clear self.rects_layer.controls and
   self.highlight_layer.controls, then for every rect draw the blue border
   Container, the label Container and the yellow line highlights (with the
   Region 1 rule of DoD-3). At the end set `self._overlay_scale =
   self.zoom_scale`. It does NOT take self.selections_lock itself (every
   caller already holds it; in the app it is a threading.RLock, app.py line
   56, but tests/test_marks_to_rects.py's get_app replaces it with a plain
   threading.Lock, so taking it again would hang the tests) and does NOT
   call update().
2. _update_selections_ui calls `self._redraw_overlays()` at the place where
   that code was, still inside its `with self.selections_lock:` block. The
   right-panel part of _update_selections_ui (the list rows, text, buttons)
   stays in _update_selections_ui.
3. At the END of the existing override `_update_viewer`, add: if
   `getattr(self, "_overlay_scale", None)` is not None AND it differs from
   self.zoom_scale, then, all inside ONE `with self.selections_lock:` block:
   check the condition again, call self._redraw_overlays(), and update
   highlight_layer and rects_layer the way _update_selections_ui does (only
   when they have a page). The update() calls must be inside the lock.
   Why: flet runs event handlers on parallel threads without serializing
   them; rebuilding a control list while another thread updates it crashed
   the viewer on 2026-07-28 ("assert self.__uid is not None", see
   .nightly/ROADMAP.md "パン中のクラッシュ"). Task 30c fixed it by moving
   whole layers on pan and by locking every rebuild. Keep both.
   - _update_viewer must NOT call _update_selections_ui: that rebuilds the
     right panel and would destroy a TextField the user is typing in.
   - _update_viewer is also called on every pan-drag event with an unchanged
     scale (app.py around line 1256). Then nothing is redrawn.

Do NOT change the tree shape. Four existing tests (test_rtl_label.py,

### DoD-5 -- red break marks while editing (D)

Only the right-panel editor (the `if is_editing:` branch in
_update_selections_ui). The editor drawn on the image
(_update_inline_editor / _commit_inline_edit) is NOT changed.

1. Keep a reference to the header ft.Text of the row (`header_text`).
2. The TextField's value is `add_break_marks(display_text)`.
3. Set `tf.on_change` to a handler that ONLY sets
       header_text.value = f"{rect.label}{label_suffix} [改行 {n}]:"
   with n = count_line_breaks(strip_break_marks(tf.value)), and calls
   header_text.update() if header_text.page. It must NOT change tf.value
   (that can move the cursor) and must NOT call _update_selections_ui.
   A break the user types with Shift+Enter is counted at once but gets no
   mark until the editor is opened again. That is intended.
4. In the METHOD `SelectableImageViewer.commit_edit(self, rid, new_text)`
   (app.py around line 1626) store `strip_break_marks(new_text)` instead of
   `new_text`. This is the single place the marks are removed; both Save
   (button) and Enter (on_submit) reach it. Do not add a second strip in the
   closures.
5. The non-editing display (`content_area = ft.Text(display_text, ...)`) and
   the header count when not editing are unchanged (no marks).

Nothing else in app.py changes. Do not touch rtl_rect, restore_rect,
delete_rect, start_region_ocr, the export, the label text format, or the
inline editor. Do not change custom_gui/region_stats.py.
