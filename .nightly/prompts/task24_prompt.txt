1. PURPOSE
--------------------------------------------------------------------------------
The user's exact words:

    "リアルタイム修正（右側の枠に表示されている文字を F2キーを押下することで
     編集可能とする）"
    (Real-time correction: make the characters shown in the right-hand panel

OCR of historical documents is never perfect. The user wants to fix mistakes
without leaving the application, and the corrected text is what should be
exported.

--------------------------------------------------------------------------------
2. DECISIONS ALREADY MADE - IMPLEMENT THESE, DO NOT REDESIGN
--------------------------------------------------------------------------------
    1. The edited text is what gets EXPORTED.
    2. The raw OCR text is KEPT SEPARATELY and is never overwritten, so the user
       can revert a region to the original OCR output.
    3. An edit belongs to ONE REGION of ONE IMAGE. Editing region 1 of page 5
       must not affect region 1 of page 6.

5. DEFINITION OF DONE
--------------------------------------------------------------------------------
[A] An "active region" concept exists.
    - Clicking a region card in the right-hand panel makes it the ACTIVE region.
    - The active card is visually obvious (for example a thicker or coloured
      border). Exactly one region is active at a time.
    - The active region must survive `_update_selections_ui()` rebuilds. Store
      the active region's rect_id, not the widget.
    - If no region has been clicked, the most recently added region is active.
    - Switching to another image clears or re-resolves the active region so it
      never points at a region belonging to a different image.

[B] F2 starts editing the active region.
    - Pressing F2 replaces that region's read-only ft.Text with an editable
      ft.TextField(multiline=True) pre-filled with the CURRENT text (the edited
      text if one exists, otherwise the OCR text).
    - Also provide a mouse route: an edit icon button (ft.Icons.EDIT) on each
      region card that does the same thing. Keyboard-only is not acceptable for
      a desktop app.
    - Pressing F2 when no region exists must do nothing and must not raise.

[C] Committing and cancelling.
    - There must be an obvious way to COMMIT the edit (for example a save icon
      button, and/or Ctrl+Enter) and an obvious way to CANCEL it (for example an
      Escape key and/or a cancel button). Whichever you choose, they must be
      visible in the UI, not hidden shortcuts only.
    - Commit stores the text. Cancel discards it and restores what was shown
      before the edit started.
    - While a TextField is focused and the user types, global shortcuts must NOT
      hijack the keystrokes. In particular typing "n" inside the field must not
      trigger the Ctrl+N navigation, and F2 must not restart the edit. State in
      your report how you prevented that.

[D] Edits are stored per image AND per region, and survive everything.
    - Store edited text in a GUI-free structure, keyed by image path and
      rect_id, for example an "edits" entry inside `self.image_states[path]`.
    - An edit must survive: panning, zooming, window resize, adding another
      rectangle, OCR completing afterwards, navigating to another image and
      coming back.
    - Deleting a region must delete its edit too, so a NEW region that happens to
      reuse the same rect_id can never inherit a stale edit.

[E] Reverting is possible.
    - Each edited region offers a way to restore the original OCR text
      (for example an ft.Icons.RESTORE button, shown only when an edit exists).
    - After reverting, the region shows the OCR text again and exports the OCR
      text.
    - The raw OCR result must never be modified. Reverting simply drops the edit.

[F] Edited regions are visually marked.
    - A region whose text has been edited must be distinguishable at a glance
      from one showing raw OCR, for example an "(edited)" suffix on the label or
      a small icon. A user must never be unsure whether they are looking at OCR
      output or their own correction.

[G] Export uses the edited text.
    - Extend `custom_gui/exporter.py` ADDITIVELY:

          build_export_rows(image_name, rects, ocr_results, edited_texts=None)

      where `edited_texts` is a dict {rect_id: str}. When a rect_id is present
      there, its text is used INSTEAD of the assembled OCR text.
    - `line_count` keeps meaning "how many OCR lines fell inside the rectangle".
      It is NOT the number of lines in the edited text. Document this in the
      docstring.
    - The default `edited_texts=None` MUST preserve today's behaviour exactly,
      because tests/test_exporter.py already asserts it and you may not modify
      that file.
    - The export call site in app.py passes the current image's edits.

[H] Tests - `tests/test_text_edit.py`, no GUI, no real OCR.
    Concrete assertions. Put the edit store logic in a GUI-free helper so it can
    be tested directly. At minimum:
      (a) Setting an edit for image A / rect "1" then reading it back returns
          exactly that string.
      (b) An edit for image A / rect "1" does NOT appear for image B / rect "1".
      (c) Deleting region "1" removes its edit; adding a new region that reuses
          rect_id "1" then reads back NO edit.
      (d) Reverting removes the edit and the raw OCR line list is unchanged -
          assert the OCR list is identical (same length and same text values)
          before and after.
      (e) build_export_rows with edited_texts={"1": "corrected text"} produces
          "corrected text" in row 0's text field, while row 1 (not edited) still
          contains its assembled OCR text - assert both exact strings.
      (f) build_export_rows with edited_texts=None produces exactly the same
          rows as calling it without the argument at all - assert equality of
          the two results.
      (g) With an edit applied, `line_count` still equals the number of OCR lines
          inside the rectangle, NOT the line count of the edited string. Use an
          edited string with a different number of newlines to make this
          meaningful, and assert the exact integer.

[I] Regression safety.
    - `python -m pytest tests/ -v` must pass completely (61+ tests).
    - Do NOT modify custom_gui/ocr_bridge.py, custom_gui/region_filter.py,
      custom_gui/selection.py, custom_gui/text_assembler.py,
      custom_gui/image_sequence.py.
    - Do not modify the pure functions in custom_gui/viewer.py.
    - Everything a human has verified must keep working: rectangle selection,
      the Select/Pan toggle, panning, yellow highlights, the "Region N" label
      drawn OUTSIDE the rectangle, async OCR with its progress ring, CSV/TXT
      export, folder loading and Prev/Next/Ctrl+N navigation.
    - Guard every `.update()` call on a control with `if self.page:`.
    - Do not run real OCR in your tests.
