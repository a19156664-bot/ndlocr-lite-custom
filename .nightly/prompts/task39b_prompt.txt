1. WHAT HAPPENED
================================================================================
Task 39 asked for persistence of rectangles, edited texts and the 広告 / 表紙
mark. The pure module was delivered and is good. The wiring into the
application was not. The commander ran the real widgets and got 7 failures
out of 7 checks. Nothing is written to disk and nothing is ever restored.

There were four defects. Read all four before you write any code.

DEFECT 1 - `work_state` is never imported
    `custom_gui/app.py` calls `work_state.save_work_state(...)` inside
    `_persist_work_state`, but the file has no
    `import custom_gui.work_state as work_state`. Every call raises
    NameError.

DEFECT 2 - the NameError is swallowed
    `_persist_work_state` ends with

        except Exception:
            pass

    so the NameError never surfaces. The user sees a normal save and the
    disk stays empty. This is the worst kind of failure: silent. The
    commander's own instruction to swallow write errors is what made it
    possible, and section 4[B] below narrows it.

DEFECT 3 - restore does not exist
    Neither `_switch_image` nor `__init__` calls `load_work_state`. The
    entire second half of the feature is missing.

DEFECT 4 - only 3 of the 6 mutation points persist
    Wired:     _on_pan_end, commit_edit, _on_mark_click
    NOT wired: delete_rect, restore_rect, rtl_rect

And the test file `tests/test_persistence.py` did not even parse -
`IndentationError` on line 22 - which stopped pytest during COLLECTION, so
the whole suite refused to run. It has been deleted. You are writing it from
scratch.

            pass

        except (OSError, TypeError, ValueError):

    Rationale, and this is the whole point of the change: a disk that is

    AttributeError or an ImportError is a PROGRAMMING mistake and must be
    allowed to crash loudly in the test suite instead of hiding for a day.
    Do NOT widen this back to `Exception`. Do NOT add a `finally`. Do NOT
    log and continue.

    In custom_gui/app.py, add `self._persist_work_state()` AFTER the state
    has changed in each of:

        delete_rect     (inside _update_selections_ui, ~line 1222 on master)
                        after delete_by_id and the `del self.edits[rid]`
        restore_rect    (~line 1244) after the edit is removed
        rtl_rect        (~line 1258) after self.edits is set or removed

    Put the call after the existing `self._update_selections_ui()` in each
    one, so the UI updates first and a slow disk cannot delay the redraw.

    Do NOT call `_persist_work_state` from inside `_update_selections_ui`
    itself. That method also runs from background OCR threads and from pure
    redraws; a write hung off it would persist state that no user action
    produced.

    The restored `SelectionContainer` is built with `restore(...)`, fed
