================================================================================
1. WHAT THE USER ASKED FOR
================================================================================
    "③ 広告ボタンを作成してください。
        広告ボタン機能：画像名（TAB）【広告】を出力。【広告】は固定文字です。
     ④ 表紙ボタンを作成してください。
        表紙ボタン機能：画像名（TAB）【表紙】を出力。【表紙】は固定文字です。"

The user proof-reads a scanned magazine page by page. Most pages get regions
drawn and OCR text corrected. But an advertisement page or a cover page has
nothing worth extracting - the user only wants ONE line recorded for it so the
final list has no gaps.

The user chose "the button writes to the file the moment it is pressed".

The commander added one thing on top, because writing only to the file loses
the information:

    An advertisement page has NO rectangles, so `_collect_all_export_pages`
    skips it, so it would never appear in the all-pages export. The stamp must
    therefore ALSO be remembered in the page's state, and the all-pages export
    must include stamped pages.

================================================================================
2. THE FIXED STRINGS
================================================================================
    広告 button  ->  "【広告】"
    表紙 button  ->  "【表紙】"

Those are the exact characters, including the black lenticular brackets
U+3010 and U+3011. They are FIXED - never derived from OCR, never edited by
the user, never translated, never configurable.

A stamped line is exactly:

    <image basename>\t【広告】

one TAB (U+0009), no spaces around it, terminated by a single "\n". The image
name is the basename with its extension, the same string
`build_export_rows` puts in "image_name" - for a PDF page it is the rendered
page's PNG basename, exactly as the CSV already records it.

3. DELIVERABLES
================================================================================
[A] A new pure module: custom_gui/page_marks.py

    No flet, no GUI. Small enough to test exhaustively.

        MARK_AD    = "【広告】"
        MARK_COVER = "【表紙】"

        def mark_line(image_name, mark) -> str
            Returns "<basename>\t<mark>" with NO trailing newline.
            image_name may be a full path; take the basename, and handle a
            Windows path with backslashes the way exporter.build_export_rows
            already does (`image_name.replace('\\', '/')`).

        def append_mark_line(txt_path, line) -> bool
            Appends line + "\n" to txt_path as utf-8, creating the file if it
            does not exist. Returns True if it wrote, and False if the exact
            same line is ALREADY present in the file - in which case it must
            NOT write anything. This is the double-press guard: the user will
            press the button twice by accident and must not get two identical
            lines.
            Comparison is against the file's lines with their trailing
            newlines stripped, exact match, no normalisation.
            The parent directory is assumed to exist; let an OSError
            propagate.

[B] Two toolbar buttons

        ft.TextButton("広告")  tooltip "このページを【広告】として記録"
        ft.TextButton("表紙")  tooltip "このページを【表紙】として記録"

    Place them immediately after the two save icons Task 35 added. Keep them
    as attributes `self.btn_mark_ad` and `self.btn_mark_cover` so tests can
    find them.

[C] Pressing a button does THREE things, in this order

        1. Remember the stamp:
               self.mark = "【広告】"
           and store it in the current image's entry of `self.image_states`
           under the key "mark", so it survives switching pages and coming
           back. `_switch_image` must save and restore it exactly the way it
           already saves and restores "selections", "ocr_results" and "edits".
           A page that was never stamped has mark None.

        2. Append to the file, immediately, with no dialog:
               csv_path, txt_path = export_targets(self.image_src, "current",
                                                   pdf_source)
               wrote = append_mark_line(txt_path, mark_line(self.image_src, mark))
           `pdf_source` is resolved exactly as Task 35 resolves it: the first
           element of `self.pdf_page_map[self.image_src]` when the current
           image is a PDF page, otherwise None. So a PDF page's line lands
           next to the SOURCE PDF, never in the temp folder.

        3. Report in the status line - NOT in a dialog:
               wrote is True   -> "【広告】を <txt file name> に記録しました"
               wrote is False  -> "【広告】は既に記録済みです"
               OSError         -> "記録できませんでした: <the error>"
           A modal every time would be unbearable when stamping a run of
           advertisement pages. Do not open an ft.AlertDialog here.

    Pressing 広告 on a page already stamped 表紙 replaces the stamp with
    【広告】 and appends the 【広告】 line; it does NOT remove the 【表紙】 line
    already written to the file. Removing a line from a file is out of scope.

[D] The stamp is visible

    While the current page is stamped, show the stamp text at the top of the
    right hand panel, above the region list, as
    ft.Text("【広告】", weight=ft.FontWeight.BOLD). When the page has no
    stamp, show nothing there. Keep it as `self.mark_label` so a test can read
    it. It must update when the page is stamped and when the user switches to
    another page.

[E] The all-pages export includes stamped pages

    `_collect_all_export_pages` today skips any image with no rectangles.
    Change it so that an image with NO rectangles but WITH a mark is included,
    contributing exactly one row:

        {"image_name": <path>, "region_id": "mark", "x1": 0, "y1": 0,
         "x2": 0, "y2": 0, "line_count": 0, "text": "【広告】"}

    so the TXT line is "<name>\t【広告】" and the CSV gets one row with the
    fixed string in its text column. An image with rectangles AND a mark
    keeps its rectangles and gets the mark row FIRST, before its regions - the
    stamp describes the whole page.

    A stamped page with no rectangles must NOT be counted as "skipped: OCR not
    finished", and must NOT require OCR to have run. Stamping is independent
    of OCR - the user stamps advertisement pages precisely so they never have
    to OCR them.

    Do this by building the rows in app.py. Do NOT change
    custom_gui/exporter.py, and do NOT change the signature or behaviour of
    build_export_rows or build_export_rows_multi.

[F] The per-page save is consistent with the stamp

    When the current page is stamped and the user presses "このページを保存",
    the written TXT must contain the "<name>\t【広告】" line too - reuse the
    same row-building rule as [E]. Otherwise saving the page would overwrite
    the file and silently delete the line the button had appended. This is the
    single most important regression in this task: WRITE A TEST FOR IT.
