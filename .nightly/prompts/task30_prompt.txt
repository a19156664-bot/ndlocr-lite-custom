Task 30: [FEATURE] Wire the OCR cache into the GUI - "Pre-OCR all pages"

You MUST read AGENTS.md at the repository root and follow its rules.

custom_gui/ocr_cache.py and custom_gui/batch_ocr.py are merged, tested and
verified against the real OCR model. They are NOT called from the GUI yet.
This task connects them. Do not modify either module.

================================================================================
1. WHY
================================================================================
Measured by the commander on this machine with the real model:

    model load ......... ~25 s   (paid every time src/ocr.py starts)
    OCR per page ....... ~13 s
    -> opening a page today costs ~38 s, every page, every session

    batch of 3 pages ... 63.8 s total  (one model load)
    second run ......... 0.002 s       (served from cache)

The cached output was verified byte-for-byte identical to per-page OCR: text,
bounding boxes, is_vertical and confidence all match. Batching costs nothing in
quality.

So: let the user press a button to OCR every page once, then serve every page
from cache instantly.

================================================================================
2. SCOPE - READ THIS TWICE
================================================================================
IN scope : ordinary image files (.jpg .jpeg .png .tif .tiff)
OUT of scope: PDF pages. Deliberately deferred to Task 31.

PDF pages are rendered into `self.pdf_cache_dir`, which is
`tempfile.mkdtemp(prefix="ndlocr_pdf_")` - a directory that is DELETED when the
process ends and has a DIFFERENT path every run. Caching against those paths
would write cache files that can never be found again.

Therefore, everywhere you touch the cache:

    if path in self.pdf_page_map:   -> do NOT read the cache, do NOT write it

PDF pages keep working exactly as they do today, through the existing lazy OCR.
They are slower; that is expected and accepted for now.

3. DELIVERABLES
================================================================================
3.1 [A] Cache-first reading in `_switch_image`

    Today `_switch_image` ends with:

        if self.ocr_state in (OcrState.IDLE, OcrState.WAITING) and self.page:
            self.start_ocr(self.page)

    Before that, when the page state is IDLE and the path is NOT in
    self.pdf_page_map, try `ocr_cache.load_cache(path)`. On a hit:

        state["ocr_results"] = <the cached list>
        state["ocr_state"]   = OcrState.DONE
        self.ocr_results     = <the cached list>
        self.ocr_state       = OcrState.DONE

    and do NOT call start_ocr. The status line then shows the existing
    "Lines: N" wording with no new vocabulary. Highlights, region filtering and
    export must work exactly as if the OCR had just run - they read
    self.ocr_results, so nothing else should need changing.

    On a miss, behave exactly as today.

    A cache hit must be FAST. Do not call load_cache more than once per switch.

3.2 [B] The "Pre-OCR all pages" button

    Add ONE ft.IconButton to the toolbar, positioned immediately after
    self.btn_open_pdf in the visual order:

        self.btn_batch_ocr = ft.IconButton(
            icon=ft.Icons.DOCUMENT_SCANNER,
            tooltip="Pre-OCR all pages (images only; PDF pages are skipped)",
            on_click=self._on_batch_ocr_click,
        )

    Note the capitalised ft.Icons - flet 0.27.6 requires it.

    Clicking it when idle starts the batch. Clicking it WHILE RUNNING cancels
    (see [D]). Change the icon to ft.Icons.CANCEL and the tooltip to
    "Cancel pre-OCR" while running, and restore both when it finishes.

3.3 [C] Running the batch

    Collect the candidate pages from the CURRENT sequence, excluding anything in
    self.pdf_page_map. If there are none, set self.latest_region_info to say so
    and stop - do not start a subprocess.

    Run `batch_ocr.run_batch` on a worker thread via `page.run_thread`, exactly
    the pattern `start_ocr` already uses. Never block the UI thread.

    Pass:
        progress      -> updates the status line (see [E])
        should_cancel -> returns self._batch_cancel_requested

    While the batch runs, LAZY OCR MUST NOT START. Two OCR processes would each
    load the model and fight for the CPU on this 4-core machine. Add a flag,
    for example self.batch_running, and make `start_ocr` return immediately
    when it is set. Turning pages during a batch must stay possible and must
    not crash; those pages simply show "OCR waiting" or their cached result.

    When run_batch returns:
      - clear the flag and restore the button
      - report the outcome in self.latest_region_info, including the number of
        PDF pages that were excluded, for example:
            "Pre-OCR complete: 152 cached, 12 PDF pages skipped"
        and on failures include the count:
            "Pre-OCR finished: 150 cached, 2 failed"
      - refresh the CURRENT page from the cache so the user immediately sees
        the result of the page they are looking at, without a manual page turn.

3.4 [D] Cancelling must not throw away completed work

    run_batch already harvests everything that finished before the cancel and
    caches it - that behaviour is tested and verified. Your job is only to set
    the flag and report honestly, for example:
            "Pre-OCR cancelled: 47 cached, 117 remaining"
    Pressing the button again must resume, and resuming must NOT redo the 47
    pages already cached - plan_batch handles that for you.

3.5 [E] Progress in the status line

    Store the progress on the viewer, for example
    self.batch_progress = (done, total) or None, and have `_get_status_message`
    append a segment when it is not None:

            ... | Pre-OCR: 37/164

    Do NOT change or reorder any of the existing segments of that string.
    tests/test_async_ocr.py and other existing tests assert on the current
    wording. Append only.

    IMPORTANT - the last update. batch_ocr polls the output directory about once
    a second, so the final page can complete inside the last sleep and never be
    reported. After run_batch returns, set the progress explicitly to the final
    counts before clearing it, so the user never sees the bar stop at 163/164.

3.6 [F] Persist lazy OCR results too (lowest priority - do this last)

    In `_on_ocr_complete`, when OCR succeeded and the path is NOT in
    self.pdf_page_map, call `ocr_cache.save_cache(path, results)`. Then a user
    who simply browses pages builds the cache as a side effect, and a later
    batch skips them.

    Never cache a failed or empty-because-of-error result. If save_cache raises,
    swallow it and carry on - a cache write failure must never break OCR.

================================================================================
4. DEFINITION OF DONE
================================================================================
[1] Cache hit path: switching to a page with a valid cache sets DONE and does
    NOT call run_ocr_and_parse.
[2] Cache miss path: unchanged behaviour, lazy OCR still runs.
[3] PDF-backed pages never read or write the cache, and still work.
[4] The button starts the batch on a worker thread and the UI stays responsive.
[5] Lazy OCR cannot start while a batch is running.
[6] Cancel works, keeps completed work, and resuming skips what is already done.
[7] The status line shows progress, appended - existing segments unchanged.
[8] The final progress value is correct, not one short.
[9] `python -m pytest tests/ -v` passes completely (111+ tests).
