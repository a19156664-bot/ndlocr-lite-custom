Task 32: [UX] Enter commits an F2 correction; Shift+Enter inserts a line break

You MUST read AGENTS.md at the repository root and follow its rules.

Small, self contained. One control, one behaviour.

================================================================================
1. WHAT THE USER ASKED FOR
================================================================================
"右枠での修正完了後にENTERキーを押下で保存を実行。
 理由：保存ボタンの押下忘れの防止および効率化。"

Today, correcting a region's text in the right hand panel means clicking the
small save (disk) icon. Users forget to click it and lose the correction. The
user wants Enter to commit.

================================================================================
2. THE API IS AVAILABLE - THE COMMANDER VERIFIED IT
================================================================================
flet 0.27.6's ft.TextField accepts `multiline`, `shift_enter` and `on_submit`
together. Verified by constructing one and reading the values back:

    multiline   = True
    shift_enter = True
    on_submit   = True

`shift_enter=True` means: Shift+Enter inserts a line break, and a plain Enter
fires `on_submit`. Do not implement your own key handling, do not add a
KeyboardListener, and do not set multiline=False - OCR text is frequently
several lines and the user must still be able to add a line break.

================================================================================
3. THE CODE AS IT IS TODAY
================================================================================
In `custom_gui/app.py`, inside `_update_selections_ui`, for the region being
edited:

    if is_editing:
        tf = ft.TextField(
            value=display_text,
            multiline=True,
            autofocus=True
        )
        content_area = ft.Column([
            tf,
            ft.Row([
                ft.IconButton(icon=ft.Icons.SAVE, tooltip="Save (Commit)",
                              on_click=lambda e, rid=rect.rect_id, tf=tf: commit_edit(e, rid, tf)),
                ft.IconButton(icon=ft.Icons.CANCEL, tooltip="Cancel",
                              on_click=cancel_edit)
            ])
        ])

and the existing handlers, in the same scope:

    def commit_edit(e, rid=rect.rect_id, text_field=None):
        self.edits[rid] = text_field.value
        self.editing_region_id = None
        self._update_selections_ui()

    def cancel_edit(e, rid=rect.rect_id):
        self.editing_region_id = None
        self._update_selections_ui()

4. DELIVERABLES
================================================================================
[A] Enter commits.

    Give the TextField `shift_enter=True` and an `on_submit` that commits
    exactly what the save button commits - the same `commit_edit`, with the
    same rect_id and the same text field. After it, `self.edits[rid]` holds the
    new text, `self.editing_region_id` is None, and the panel shows the saved
    value with the "(edited)" suffix.

    Committing through Enter and committing through the button must be
    indistinguishable in their effect. Do not duplicate the logic - route both
    to the same function.

[B] Shift+Enter still inserts a line break.

    Keep multiline=True. Do not clamp max_lines in a way that prevents this.

[C] The save and cancel buttons stay.

    Do not remove them. Not every user will discover the key, and the user only
    asked to ADD the shortcut. Update the save button's tooltip to mention it,
    for example "Save (Enter)".

[D] An empty field must behave the same on both paths.

    Whatever committing an empty string does today through the button, Enter
    must do the same. Do not add new validation.
