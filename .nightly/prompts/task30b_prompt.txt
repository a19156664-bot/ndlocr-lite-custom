2. WHAT THE COMMANDER FOUND DURING ACCEPTANCE
================================================================================
2.1 A batch can start while a lazy OCR is still running.

    `start_ocr` returns early when self.batch_running is set, so no NEW lazy OCR
    begins. But a job already in flight keeps going, so two OCR processes can
    briefly overlap, each loading the model, on a 4 core machine.

2.2 A race can overwrite a good cache with an empty result.

    Reproduced by switching pages faster than OCR completes:

        _switch_image(p) sets state IDLE, then looks up the cache and sets DONE.
        Meanwhile _on_ocr_complete for an EARLIER page fires, asks the
        scheduler what to run next, gets p, and calls start_ocr(p) - which still
        sees IDLE because the cache lookup has not landed yet.
        That OCR then completes and writes ITS result into state and into the
        cache, replacing what was there.

    In real use OCR takes ~13 s so the window is small, but it is real.

2.3 Running the test suite writes into the repository.

    tests/test_async_ocr.py and other existing tests OCR the bundled image
    resource/digidepo_2531162_0024.jpg. Task 30's [F] now caches successful
    results, so `pytest` creates

        resource/.ndlocr_cache/digidepo_2531162_0024.json

    Confirmed by deleting it and re-running the suite: it comes back. Two
    problems: the repository is dirtied, and a stale cache file can short
    circuit the cache-first path in a LATER test run, making a lazy-OCR test
    pass for the wrong reason. This project has already shipped six tests that
    could not detect the bug they were written for.

2.4 Finishing a batch resets the user's zoom and pan.

    `_run_batch_worker` ends with `self._switch_image(self.image_src)`, and
    `_switch_image` recomputes zoom_scale from calculate_fit_scale and zeroes
    offset_x / offset_y.

3. DELIVERABLES
================================================================================
[A] Count the whole folder.

    Progress must be expressed over every page the batch was asked about, with
    already-cached pages counted as already done:

        total   = len(candidate_paths)                 # 52
        done    = len(already_cached) + <finished so far>

    So the display starts at 2/52 and ends at 52/52. Do this once, in the
    viewer - do NOT modify custom_gui/batch_ocr.py, whose own callback
    legitimately reports progress over the work it was given.

[B] A visible progress bar.

    Add an ft.ProgressBar across the top of the viewer area, above the image.
    visible=False normally; visible only while a batch runs, with
    value = done / total (a float 0.0-1.0). Remove it from view when the batch
    ends. It must not disturb the existing layout when hidden, and must not
    change zoom_scale or the image area geometry - the commander verifies that
    zoom_scale stays 0.2605 for a 2218x3071 image in a 1600x900 window.

[C] Spin the ring and estimate the time left.

    While a batch runs, self.progress_ring.visible must be True.

    Estimate the remaining time from what has actually happened - measure it,
    do not hard code a per page constant:

        elapsed_per_page = (now - batch_start) / pages_finished_this_run
        remaining        = elapsed_per_page * pages_left

    Show nothing until at least one page has finished this run; there is no
    honest estimate before that. Format it for a human: "about 8 min",
    "about 40 sec". Round; do not print "7.3184 minutes".

[D] Label the button.

    Replace the ft.IconButton with a labelled control, in the same toolbar
    position (third, right after Open PDF). Zoom In / Zoom Out / Fit are
    already text buttons, so a text button is consistent. Keep the attribute
    name self.btn_batch_ocr so existing tests keep working.

        idle    : text "Pre-OCR All"   tooltip explaining PDF pages are skipped
        running : text "Cancel"        tooltip "Cancel pre-OCR"

    Use ft.Colors / ft.Icons with capitals if you use them at all - flet 0.27.6
    requires it.

[E] Wait for an in-flight lazy OCR before starting the batch.

    On click, if a lazy OCR is currently RUNNING, do not launch run_batch
    immediately. Set batch_running so nothing new starts, then wait for the
    running job to finish before launching. Do this on the worker thread, not
    on the UI thread - the window must stay responsive and the button must
    already show "Cancel". Report the wait in the status, for example
    "Pre-OCR: waiting for the current page...". Cancelling during that wait
    must work and must not launch the batch.

[F] Close the cache/OCR race - ONE choke point.

    Make `start_ocr` itself consult the cache before it launches anything:
    after it has resolved target_path and state, and before
    ocr_scheduler.request_ocr, if the path is NOT in self.pdf_page_map and
    ocr_cache.load_cache(target_path) returns a list, adopt that result
    (state DONE, results stored, current view updated if it is the displayed
    page) and return WITHOUT running OCR.

    That way it does not matter who calls start_ocr, or when - a cached page can
    never be re-OCR'd and can never have its cache overwritten. Keep the lookup
    in _switch_image as well so the display path stays fast; a second call for
    the same path must not cost a second file read in the common case, so
    short circuit on state already being DONE.

    Additionally, `_on_ocr_complete` must not overwrite a state that is already
    DONE with results. If it arrives for a path whose state is DONE and whose
    ocr_results is non-empty, discard the late result and do not call
    save_cache.

[G] Stop the test suite writing into resource/.

    Two changes:

    G1. Add a .gitignore entry for the cache directory:

            .ndlocr_cache/

    G2. Make the tests that OCR the bundled image work on a COPY under pytest's
        tmp_path instead of on resource/ itself. You MAY edit these existing
        test files FOR THIS PURPOSE ONLY:

            tests/test_async_ocr.py
            tests/test_layout_stability.py
            tests/test_missing_image_recovery.py
            tests/test_flet_constants.py

        The ONLY permitted change is where the image file comes from - copy
        resource/digidepo_2531162_0024.jpg into tmp_path with shutil.copy2 and
        point the test at the copy. NOT ONE ASSERTION MAY CHANGE. No test may
        be relaxed, skipped, renamed or deleted. If making a test work on a copy
        would require changing an assertion, STOP and report it instead.

        Prove it: delete resource/.ndlocr_cache, run the full suite, and show
        that `git status` is clean afterwards. Put that output in your report.

[H] Do not reset zoom and pan when a batch finishes.

    Replace the `self._switch_image(self.image_src)` call at the end of
    `_run_batch_worker` with a refresh that adopts the cached result for the
    CURRENT page and updates the status, highlights and region list - without
    touching zoom_scale, offset_x or offset_y, and without reloading the image.
    If the current page is in self.pdf_page_map, there is nothing to adopt.
