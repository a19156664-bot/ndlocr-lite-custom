Task 38: [UX] Ctrl+S saves the page, Enter confirms, and the dialog offers the next page

You MUST read AGENTS.md at the repository root and follow its rules.

Three related changes to the save flow. All of them are about keeping the
user's hands on the keyboard while they proof-read page after page.

================================================================================
1. WHAT THE USER ASKED FOR
================================================================================
    "Ctrlボタン+Sボタンで現在のページ保存（ショートカット）。
     ページ保存は現在OKボタンを押下しておりますが、エンターキーの押下でも
     保存できるようにしてください。また、OKボタン押下後に次のページに進むかの
     ウィンドウの表示をお願いいたします。"

Asked whether the confirmation and the next-page prompt should be two dialogs
or one, the user chose ONE dialog - two dialogs would mean pressing Enter
twice. So the finished flow is:

    Ctrl+S  ->  saves  ->  one dialog  ->  Enter  ->  next page

Two keystrokes per page.

2. THE CODE AS IT IS TODAY
================================================================================
custom_gui/app.py, `_do_write_and_show_done(scope, csv_path, txt_path)` writes
the files and then opens

    self._save_dialog = ft.AlertDialog(
        title=ft.Text("保存しました"),
        content=ft.Text(f"{csv_path}\n{txt_path}"),
        actions=[ft.TextButton("OK", on_click=close_dialog)],
        modal=True
    )
    if self.page:
        self.page.open(self._save_dialog)

`_show_overwrite_dialog` opens the two-button 上書き確認 dialog, whose
上書き保存 action calls `_do_write_and_show_done`. On a write error the same
method opens a "保存できませんでした" dialog with one OK button.

The global keyboard handler lives in `main()` at the bottom of the file:

    def on_keyboard(e: ft.KeyboardEvent):
        if viewer.editing_region_id is not None or viewer.inline_editing_region_id is not None:
            if e.key == "Escape":
                if viewer.inline_editing_region_id is not None:
                    viewer._cancel_inline_edit()
            # Suppress global shortcuts while editing text
            return

        if e.key == "N" and e.ctrl:
            if viewer.btn_next and not viewer.btn_next.disabled:
                viewer._on_next_click(None)
        elif e.key == "F2":
            ...

    page.on_keyboard_event = on_keyboard

Moving to the next page is `viewer._on_next_click(None)`, guarded by
`viewer.btn_next.disabled`, which is already False only when a next page
exists.

`autofocus=True` on a dialog action is how Enter reaches the button: the
button takes keyboard focus when the dialog opens, and Enter activates the
focused button. Do NOT implement Enter by adding a key handler that inspects
whether a dialog is open - the dialog owns focus and the global handler is not
a reliable place to do this.

4. DELIVERABLES
================================================================================
[A] Ctrl+S saves the current page

    In `on_keyboard`, add a branch for `e.key == "S" and e.ctrl` that calls
    `viewer._start_export("current")`.

    It must sit AFTER the existing early return, so Ctrl+S does nothing while
    the user is typing in the right hand panel or in the inline editor. That
    early return is deliberate; do not move it or weaken it.

    Ctrl+S must go through `_start_export` exactly like the toolbar icon, so
    all of its validation still applies: "Nothing to export" when there are no
    rectangles, "OCR not finished - cannot export yet", and the 上書き確認
    dialog when the file already exists. Do not duplicate that logic.

    Do not add Ctrl+Shift+S, and do not touch Ctrl+N or F2.

[B] The done dialog becomes ONE dialog that also offers the next page

    Replace the single-OK dialog in `_do_write_and_show_done` with:

        title    ft.Text("保存しました")
        content  the two absolute paths, then a blank line, then
                 ft.Text("次のページへ進みますか？")
        actions  ft.TextButton("ここに残る")  -> closes, stays on this page
                 ft.TextButton("次へ", autofocus=True)
                                            -> closes, then advances
        modal    True

    "次へ" is the LAST action and the autofocused one, so Enter advances.

    Advancing means calling `self._on_next_click(None)` - the same path the ▶
    button uses. Close the dialog FIRST, then advance, so the page switch
    happens with no dialog on screen.

    WHEN THERE IS NO NEXT PAGE
        If `self.btn_next` is None or `self.btn_next.disabled` is True, the
        dialog must NOT offer 次へ. Show a single ft.TextButton("OK",
        autofocus=True) instead, and leave the "次のページへ進みますか？" line
        out of the content. Enter then just closes it. The user is on the last
        page; offering a move that cannot happen would be a lie.

    WHEN THE SCOPE IS "all"
        A whole-book export is not a per-page step, so do NOT offer 次へ after
        it. Show the single autofocused OK, same as the last-page case.
        `_do_write_and_show_done` already receives `scope`; branch on it.

[C] Enter works on the completion dialogs

    Give the affirmative action `autofocus=True`:

        the 次へ button                                  -> autofocus
        the OK button of the last-page / all-pages form  -> autofocus
        the OK button of the "保存できませんでした" error dialog -> autofocus

[D] The 上書き確認 dialog gets NO autofocus - this is deliberate

    Do NOT put autofocus on 上書き保存 or on キャンセル. Enter must not be able
    to overwrite a file the user has not looked at. The commander decided this
    explicitly; if you think it is inconsistent, say so in your report but do
    NOT change it.

[E] Nothing else about saving changes

    The file names, the folders, the encodings, the row building, the mark
    rows from Task 36, the status messages, and the behaviour of the toolbar
    icons all stay exactly as they are.
