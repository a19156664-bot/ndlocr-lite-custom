================================================================================
Task 46: A button that turns detected cyan marks into selection rectangles
================================================================================

## 1. Purpose and background

The user marks the areas to OCR by hand with a cyan highlighter, then has to
re-draw every one of them with the mouse. Task 45 shipped the detector that
finds them. This task adds the one button that uses it.

Measured on the 52 real pages (2026-08-27): 38 of 52 pages carry marks,
118 regions in total, up to 11 on a single page. Drawing those by hand is the
work this button removes.

`custom_gui/mark_detector.py` is on master already. Its contract:

    from custom_gui.mark_detector import load_image, detect_marks

    load_image(path: str) -> numpy.ndarray (BGR)
        raises FileNotFoundError when the file is missing
        raises ValueError when the bytes are not a decodable image

    detect_marks(image_bgr) -> List[MarkRegion]
        MarkRegion is a dataclass with:
            .bbox : Tuple[int, int, int, int]   -> (x1, y1, x2, y2) ORIGINAL pixels
            .kind : str                          -> "box" or "line"
        The list is sorted by (y1, x1) and is deterministic.

`.bbox` is already in the same (x1, y1, x2, y2) convention as
`SelectionRect.bbox`, so it can be handed to `SelectionContainer.add()`
unchanged. **Do not convert it to (x, y, w, h).**

### DoD-2 — the handler

    def _on_marks_to_rects_click(self, e):

Behaviour, exactly:

    1. Read the current page image with load_image(self.image_src).
       Catch FileNotFoundError, ValueError and OSError. On any of them:
       set self.latest_region_info to a message containing the word
       "読み込めません", call self._update_status(), and RETURN.
       **The application must not raise out of this handler, ever.**
    2. regions = detect_marks(img)
    3. If regions is empty: set self.latest_region_info to a message containing
       "マークが見つかりません", call self._update_status(), and RETURN
       **without changing any other state**. Existing rectangles, self.edits,
       active_region_id and inline_editing_region_id must all be untouched.
    4. Otherwise, for each region in order, add it unless the same area is
       already present (see DoD-3):
           self.selection_container.add(region.bbox)
    5. Set self.latest_region_info to a message that contains the number added,
       for example:  マークから 10 個の矩形を作りました（囲み 1・傍線 9）
    6. Call self._update_selections_ui() and self._persist_work_state().

**Do not start OCR from this handler.** Do not open the inline editor. Do not
change the mode. Do not spawn a thread - detection takes about 0.2 s per page,
measured.

**Locking:** `_update_selections_ui` and `_persist_work_state` acquire
`self.selections_lock` themselves. If you take the lock, release it before
calling them, or the application deadlocks. This was the serious defect of
Task 30c; never remove or weaken a `with self.selections_lock:` block.

### DoD-3 — pressing the button twice must not duplicate

Before adding a detected region, skip it when a rectangle already in
`self.selection_container.get_all()` has a bbox within **2 pixels on all four
sides**. Use a tolerance, not equality: existing rectangles were produced by
`calculate_normalized_bbox` and hold floats, while `MarkRegion.bbox` holds ints.

Pressing the button twice on the same page must leave exactly the same number
of rectangles as pressing it once.

## 3. Tests you must write

Put them in `tests/test_marks_to_rects.py`.

**Test through the handler**, the way `tests/test_tap_to_edit.py` and
`tests/test_pan.py` already do - read one of them first and follow the same
construction pattern. Twelve tests in this project have been rejected for
mocking or bypassing the thing under test.

Build the page image in code and write it to `tmp_path`, then construct the
viewer with that file as `image_src`. Do not add any binary file to the repo.

    def make_marked_page(path, w=400, h=600):
        page = np.full((h, w, 3), 255, dtype=np.uint8)
        page[100:250, 50:300] = (255, 235, 60)     # one cyan box
        cv2.imencode(".jpg", page)[1].tofile(str(path))
        return w, h

Required cases, each an exact assertion:

    1. One cyan box on the page -> pressing the button once creates exactly
       1 rectangle, and its bbox is within 8 px of the painted area.
    2. Pressing the button twice -> still exactly 1 rectangle (DoD-3).
    3. A page with no cyan at all -> 0 rectangles created, and
       self.latest_region_info contains "マークが見つかりません".
    4. A page with no cyan, when a rectangle already exists -> that existing
       rectangle is STILL THERE afterwards, and self.edits is unchanged.
    5. self.image_src pointing at a path that does not exist -> the handler
       returns normally (no exception propagates) and
       self.latest_region_info contains "読み込めません".
    6. Two cyan boxes at different heights -> 2 rectangles, added in the order
       detect_marks returned them (topmost first).
    7. The button object exists and is present in self.controls_row.controls.
    8. A cyan box plus an already-drawn rectangle somewhere else -> the count
       becomes 2, and the pre-existing one is not modified.

Use exact values. Do not use assertGreater, assertIsNotNone, or "it exists"
checks where a number or a stated tolerance can be written.
