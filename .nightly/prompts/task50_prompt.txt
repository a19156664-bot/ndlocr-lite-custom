================================================================================
Task 50: Mark the regions that contain right-to-left horizontal text
================================================================================

## 1. Purpose and background

The magazine is from 1933. Its VERTICAL text reads top-to-bottom and the OCR
gets it right. Its HORIZONTAL text reads RIGHT-TO-LEFT, and the OCR reads it
left-to-right, so those lines come out reversed:

    局支クーヨーユニ合聯聞新   should be   新聞聯合ニユーヨーク支局
    要法念記年周十災震大東開   should be   開東大震災十周年記念法要
    片短スーユニ眞寫國英       should be   英國寫眞ニユース短片

`custom_gui/rtl.py` already fixes this. `convert_right_to_left(text)` reverses
each line and mirrors brackets, and there is already an RTL button per region.
**The user has to notice which regions need it.** Measured on the 52 pages:
**82 of the 625 lines inside marked regions are horizontal, spread over 25
pages.** Finding them by eye is the work this task removes.

**This task does NOT reverse anything automatically.** The approver decided on
2026-08-28: mark them, let the human press the existing button. Automatic
reversal would corrupt lines containing Latin text, and would hide the change
from the person checking it.

## 2. The signal is already in the data. Do not compute a heuristic.

`custom_gui/ocr_bridge.parse_ocr_json` already returns, for every line:

    {'text': '行資社合瞬間新',
     'bbox': (291.0, 17.0, 715.0, 50.0),
     'confidence': 0.869,
     'is_vertical': False,          <-- THIS
     'source_image': '...jpg'}

`is_vertical` comes from the OCR's own `isVertical` field, produced by its
layout model.

**Do NOT judge orientation from the bounding box aspect ratio.** The commander
tried that first and measured it against `is_vertical` over all 2,235 lines:
they agree on 97.76% and disagree on 50 lines, and **in every one of those 50
the aspect ratio is wrong** - they are 1-3 character fragments such as `(一)`,
`100`, `す。` sitting in vertical text, whose boxes happen to be nearly square.

Use `is_vertical`. Nothing else.

## 3. Definition of Done (verifiable)

### DoD-1 — the predicate, in `custom_gui/rtl.py`

Add to that file, changing nothing already in it:

    RTL_MIN_CHARS = 2

    def needs_rtl(line: dict) -> bool:
        """True when this OCR line is horizontal text that reads right-to-left."""

Rules, each of which must have a test:

    a. line["is_vertical"] is True  -> False
    b. line["is_vertical"] is False and len(line["text"]) >= RTL_MIN_CHARS -> True
    c. line["is_vertical"] is False and len(line["text"]) < RTL_MIN_CHARS -> False
       (a single character reads the same reversed; flagging it is only noise)
    d. A line dict missing "is_vertical" -> False. Do not raise.
    e. A line dict missing "text" -> False. Do not raise.

`rtl.py` must stay free of any import from `custom_gui` and free of flet, cv2
and numpy. It currently imports nothing at all. Keep it that way: `needs_rtl`
only reads keys out of a plain dict.

### DoD-2 — the counter, in `custom_gui/rtl.py`

    def count_rtl_lines(lines) -> int:
        """How many of these OCR lines need right-to-left conversion."""

Returns the number of entries for which `needs_rtl` is True. An empty list
returns 0. Do not raise on a list containing malformed dicts.

### DoD-3 — the label, in `custom_gui/app.py`

In `_update_selections_ui`, the right-hand panel builds one row per region.
Inside that loop, line 1367 already computes:

    filtered_lines = filter_lines_by_region((x1, y1, x2, y2), self.ocr_results)

and line 1423 already computes the label suffix:

    label_suffix = " (edited)" if has_edit else ""

which is used on line 1470:

    ft.Text(f"{rect.label}{label_suffix} [改行 {n_breaks}]:", weight=ft.FontWeight.BOLD),

Append a second suffix when the region contains right-to-left lines. Use
`count_rtl_lines(filtered_lines)`. When the count is 0, the label must be
**byte-identical to what it is today**. When it is 1 or more, append exactly:

    " [横書き? N]"

with N the count. Example of the finished label text:

    Region 3 [横書き? 4] [改行 2]:
    Region 3 (edited) [横書き? 4] [改行 2]:

**The 横書き marker goes after `label_suffix` and before ` [改行`.**

Do not change the RTL button, `rtl_rect`, `convert_right_to_left`, or anything
else in the row. Do not reverse any text. Do not touch `self.edits`.

## 4. Tests you must write

Two new files. Do not modify any existing test.

### `tests/test_rtl_detect.py` — the predicate (pure, no flet)

    1. is_vertical True, 10 characters      -> needs_rtl is False
    2. is_vertical False, 10 characters     -> needs_rtl is True
    3. is_vertical False, 1 character       -> needs_rtl is False
    4. is_vertical False, 0 characters      -> needs_rtl is False
    5. dict without "is_vertical"           -> needs_rtl is False, no exception
    6. dict without "text"                  -> needs_rtl is False, no exception
    7. count_rtl_lines([]) == 0
    8. A list of 5 lines, 2 of which qualify -> count_rtl_lines == 2
    9. count_rtl_lines on a list containing one malformed dict counts the good
       ones and does not raise.
    10. A real reversed example: build the dict
        {"text": "局支クーヨーユニ合聯聞新", "is_vertical": False,
         "bbox": (0, 0, 400, 20)}
        assert needs_rtl is True, and assert that
        `convert_right_to_left(line["text"])` equals "新聞聯合ニユーヨーク支局".
        **This ties the detector to the existing converter.**

### `tests/test_rtl_label.py` — the label (through the viewer)

Set `app.ocr_results` directly to a small list of line dicts you build by hand,
add one rectangle covering them, call `app._update_selections_ui()`, then read
the label text back out of `app.selections_list.controls`.

    11. A region whose lines are all vertical -> the label contains
        "[改行" and does NOT contain "横書き".
    12. A region containing 2 horizontal lines -> the label contains
        "[横書き? 2]" exactly.
    13. The 横書き marker appears BEFORE " [改行" in the label string
        (assert the index order).
    14. A region with an edit applied -> the label contains "(edited)" AND
        "[横書き? " and they appear in that order.

If you cannot reach the label text through `app.selections_list.controls`, do
NOT give up and assert on an internal variable instead. Report exactly what you
found in that control tree. **Asserting on a variable instead of on what the

Use exact values. Do not use assertGreater, assertIsNotNone, or "it exists"
checks where a value can be written.
