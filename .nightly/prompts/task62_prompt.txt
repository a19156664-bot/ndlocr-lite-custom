## 1. Purpose and background

launch_viewer.py starts the confirmation viewer. Today it always:
  - reads the whole-page OCR result work/output/01_raw_ocr/<issue>.json
    (`with open(RAW_JSON, ...)`, no existence check);
  - in BrowserImageViewer.__init__, for every page i < len(pages_contents):
      parsed = normalize_page_ocr(pages_contents[i], basename)
      container, edits, mark = self._load_persisted_state(png_p)
      if the container is empty and parsed is not empty: add ONE rect that
        wraps all lines with a 15 px margin (min clamped at 0.0) -> this is
        the automatic "Region 1";
      self.image_states[png_p] = {"selections": container,
        "ocr_state": OcrState.DONE, "ocr_results": parsed,
        "ocr_error": None, "edits": edits, "mark": mark}

The whole-page OCR then shows up as (a) the text of a new frame before the
user runs "この枠だけOCR", (b) the exported text of a frame the user never
edited, (c) the automatic Region 1. The approver decided (2026-10-08) to add
a switch that starts the viewer without it. Frames are then read only by
the per-frame buttons.

Rule that must keep working (AGENTS.md 8.5): the Excel conversion drops the
text of region_id "1" (it is the automatic Region 1). Without Region 1 the
user's first frame would get id "1" and be dropped. So, with the switch
off, frame ids must start at "2".

### DoD-2 -- new file custom_gui/page_states.py

    REGION1_MARGIN = 15.0

    def page_ocr_enabled(environ) -> bool:
        """False only when environ.get("NDLOCR_PAGE_OCR", "") stripped and
        lower-cased is exactly "off". True otherwise (missing, "on", "",
        anything else)."""

    def build_page_state(parsed, container, edits, mark, page_ocr: bool) -> dict:
        """The image_states entry for one page."""

  page_ocr True (EXACTLY today's behaviour):
    if container.get_all() is empty and parsed is not empty:
        xs = [l["bbox"][0] for l in parsed] + [l["bbox"][2] for l in parsed]
        ys = [l["bbox"][1] for l in parsed] + [l["bbox"][3] for l in parsed]
        container.add((max(0.0, min(xs) - REGION1_MARGIN),
                       max(0.0, min(ys) - REGION1_MARGIN),
                       max(xs) + REGION1_MARGIN,
                       max(ys) + REGION1_MARGIN))
    return {"selections": container, "ocr_state": OcrState.DONE,
            "ocr_results": parsed, "ocr_error": None,
            "edits": edits, "mark": mark}
  page_ocr False:
    no rect is added; container.ensure_next_id_at_least(2);
    return the same dict but with "ocr_results": [] (parsed is ignored).

  Import OcrState from custom_gui.app (as launch_viewer.py does today).

### DoD-3 -- launch_viewer.py uses them

1. After RAW_JSON is defined: `PAGE_OCR = page_ocr_enabled(os.environ)`.
2. If PAGE_OCR: load RAW_JSON exactly as today. Else: do NOT open RAW_JSON
   (it may not exist), set pages_contents = [] and print
   "全体OCRを使いません（NDLOCR_PAGE_OCR=off）".
3. In BrowserImageViewer.__init__ the loop becomes:
       for i, png_p in enumerate(png_paths):
           if PAGE_OCR and i >= len(pages_contents):
               continue                      # as today: not pre-populated
           parsed = (normalize_page_ocr(pages_contents[i], os.path.basename(png_p))
                     if PAGE_OCR else [])
           container, edits, mark = self._load_persisted_state(png_p)
           self.image_states[png_p] = build_page_state(parsed, container, edits, mark, PAGE_OCR)
   (With the switch off EVERY page is pre-populated as DONE with no
   results, so the viewer never starts a whole-page OCR for a page.)
4. page.title gets the suffix "（全体OCRなし）" when not PAGE_OCR, and the
   start banner prints one more line "  全体OCR: なし" / "  全体OCR: あり".
Nothing else in launch_viewer.py changes (normalize_page_ocr stays).
