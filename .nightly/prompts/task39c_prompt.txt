1. WHERE THINGS STAND
================================================================================
The persistence feature WORKS. The commander drove the real widgets through
22 checks and every one passed: rectangles, edited texts and the 広告 / 表紙
mark are written to `.ndlocr_cache/<stem>.work.json` and restored on a fresh
viewer; deletion and edit-undo are reflected; a restored page can take a new
rectangle without corrupting an existing one; a swapped image or a corrupt
JSON restores nothing; a PDF page lands beside the PDF as
`book_p0004.work.json`; NameError propagates while OSError is swallowed; and
restoring never rewrites the file.

Two things block the merge. Both are in this task.

PROBLEM 1 - an unrequested guard broke 13 existing tests

    `_update_selections_ui` now begins with

        if not hasattr(self, 'selections_list') or not getattr(self.selections_list, 'page', None):
            return

    Nobody asked for this. It makes the whole method a no-op whenever the
    panel is not attached to a page, which is the normal condition in a
    headless test. It breaks:

        tests/test_concurrency.py    3 tests
        tests/test_edit_enter.py     6 tests
        tests/test_inline_edit.py    3 tests
        tests/test_save_direct.py    1 test

    The commander removed the single line and the suite went to 215 passed,
    including all eleven of the new persistence tests. The guard is not
    needed by anything.

PROBLEM 2 - the new tests cannot detect the defect they exist to prevent

    All eleven tests in tests/test_persistence.py bypass the event handlers.
    They do

        app.selection_container._rects.append(rect)
        app._persist_work_state()      # "simulate the _on_pan_end logic"

    so they verify `_persist_work_state` and `_load_persisted_state` in
    isolation and never verify that anything CALLS them. The commander
    re-injected six defects:

        remove _persist_work_state() from _on_pan_end     -> 215 passed
        remove _persist_work_state() from delete_rect     -> 215 passed
        remove _persist_work_state() from _on_mark_click   -> 215 passed
        remove _load_persisted_state() from _switch_image  -> 215 passed
        restore `except Exception`                         -> 1 failed
        make restore() leave _next_id at 1                 -> 4 failed

    FOUR OF SIX GO UNDETECTED - and the missing-call-site defect is exactly
    what Task 39 shipped. This project has now produced twelve tests that
    could not fail. A test that cannot fail is worthless.

    HOW TO REACH EACH MUTATION POINT

        tests do: let `_update_selections_ui` build the panel, then walk
        `viewer.selections_list.controls`, find the IconButton or TextButton
        for the region, and fire its `on_click`.
        `tests/test_edit_enter.py` and `tests/test_save_direct.py` already do
        exactly this - copy their traversal. Do NOT invent a new way, and do
        NOT reach into the closure through `__closure__` or similar tricks.

    the mark
        `viewer._on_mark_click("【広告】")` is the real handler the button
        calls. Better still, fire `viewer.btn_mark_ad.on_click`.

    restoring

        exercises `__init__`), and separately use `viewer._switch_image(img2)`
        followed by `viewer._switch_image(img1)` on a viewer whose
        `image_states` does not yet hold img1, so the `_switch_image` restore
        path is covered too. BOTH paths need a test - a defect in either one
        must fail the suite.

    Mocking the flet Page object is fine and expected. Do NOT replace
    `selections_list`, `rects_layer`, `highlight_layer`, `selection_container`,
    `image_states`, `edits`, `mark` or `btn_next` with MagicMock. Those are
    the things you are asserting about.
