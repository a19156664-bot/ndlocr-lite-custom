## 3. 「検出できず」を、そのまま穴と呼ばない

**ここが最も間違えるところである。**

| 見かけ | 実際 | どうする |
|---|---|---|
| 検出できず | **無害な注入**（振る舞いが変わっていない） | 穴ではない。台帳から消す |
| 検出できず | 元の文字列が違う（字下げ・実際のコードと不一致） | **無効**。台帳を直して測り直す |
| 検出できず | **本物の穴** | テストを足して塞ぐ（下の 4） |

**判定の順序。**

    1. 注入後のコードを自分の目で読む → 振る舞いは変わったか
    2. 変わっていないなら → 無害。穴ではない
    3. 変わっているのに落ちないなら → 本物の穴

**「見逃し」と「無効」を混ぜて数えないこと。**

## 4. 穴を塞ぐ

指揮官が自分でテストを書いてよいのは、**次の4つをすべて満たすときだけ**である。

    ・tests\ の下のテストだけ（custom_gui\ には一切触れない）
    ・20行以内
    ・目的は1種類
    ・先に壊して FAIL を見てから書く

書いたら `fix(指揮官):` を頭に付けて単独でコミットし、日報に**自分が書いた行として**残す。

**弱い assert を使わない。**

    ✗ assertGreater / assertIsNotNone / 「存在すること」だけ
    ○ assert len(rows) == 7
    ○ 呼び出しの引数まで確かめる

**「通るようになった」は証拠にならない。** `@pytest.mark.skip` でも通る。
