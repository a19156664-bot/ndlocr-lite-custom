## 1. 取り込む

**作業ツリーが要る。いまは無い。**
7月の運用では `C:\Users\user\ndlocr-work` を使い回していたが、
**2026-08-27 時点で存在しない**（`git worktree list` にも出ない）。再開時に作り直す。

    git worktree add C:\Users\user\ndlocr-work integration/task-XX

**作り直したら、台帳（`C:\Users\user\ndlocr_sabotage\inject*.py`）の先頭定数が
その場所を指しているかを確かめる。** 絶対パスで固定されている。

    jules.cmd remote pull --session <SESSION_ID> --apply

積載先は使い捨て統合ブランチ `integration/task-<開始>-<終了>`（AGENTS.md §3.1）。
**タスクごとにコミットする。** 間に挟まないと、どの変更がどの検査に対応するか追えなくなる。

## 3. 許可スコープと突き合わせる

    git diff --name-only

**指示書に書いていないファイルが1つでもあれば、そこで止める。**

あわせて見るもの。

    ✗ custom_gui\ と tests\ の外に触れていないか
    ✗ LICENCE / LICENCE_DEPENDENCEIES / NDLクレジットのヘッダに触れていないか
    ✗ train\ に触れていないか
    ✗ 既存テストの削除・スキップ・期待値変更が無いか
    ✗ 一時ファイル（*.injbak / patch*.diff）が残っていないか
    ✗ 取り消せない操作を作っていないか

    git status --untracked-files=all

### 3-1. 既存テストの期待値が変わっていないか、値で数える

    git diff tests\ | grep "^[-+].*assert" | head -40

**「テストを直して緑にした」は不合格である**（AGENTS.md §5-1）。
Task 41 では既存アサーションの変更が**6箇所の値置換のみ**であることを数えて通した。
**「たぶん大丈夫」で飛ばさない。飛ばした回は、日報にそう書く。**

### 3-2. 走っていない検査を探す

    .venv\Scripts\python.exe -m pytest tests\ --collect-only -q | tail -3

**収集数と実行数が一致していることを見る。**
母屋には `dead_tests.py`（書かれたのに走っていない検査を暴く道具）があるが、
**この箱には無い。** `--collect-only` は「集まったか」しか見ておらず、
**`assert` が1つも無い検査は素通りする。** 気になった回は自分の目で読む。
